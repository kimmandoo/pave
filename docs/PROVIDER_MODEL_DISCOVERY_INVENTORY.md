# Provider auth and model-discovery inventory

**Scope date:** 2026-09-26. Inventory of the sibling catalog's 83 provider identities, limited to source-side authentication/discovery policy and Pave's matching native route, registered grant, and model-listing adapter. This is evidence inventory, not a proposal to add providers or login flows.

**Evidence sources.** Sibling KDL rules are under `../oh-my-pi/packages/catalog/src/compat/rules/providers/`. Pave route identity/auth metadata is in `lib/provider/provider_catalog.ml` (`PC`); listing endpoint, credential policy, and adapter dispatch are in `lib/provider/model_discovery.ml` (`MD`); login dispatch is `bin/cli_auth.ml` (`CA`). Provider-specific grant sources are cited per row. `ND` means not documented in these inspected sources. `pinned` means Pave has an explicit listing adapter and fixed/route-derived endpoint; it does not prove live entitlement, terms acceptance, or that every listed ID works on the registered route. A KDL API key, `oauth-provider` marker, `allow-unauthenticated` flag, seed, or discovery label is not a Pave grant or a Pave route. A missing route/listing is not replaced by a similarly named identity. Except where a source explicitly states otherwise, client registration, terms, and account eligibility are ND.
