# Pave design rules

The product goal is a maintainable OCaml mobile coding agent. The planned feature set is not yet complete. Implement and verify each vertical capability before exposing it; never advertise unfinished catalog, LSP/DAP, subagent, extension or tool features as working.

- Provider identity, model routing, credential selection and wire serialization are separate contracts. A provider descriptor selects one supported API family and endpoint for a model; it must not send a foreign protocol through the Chat Completions adapter as a fallback. OpenAI Chat Completions and Anthropic Messages use distinct request/response wire adapters and a shared bounded SSE frame parser. A model turn produces either an assistant answer or tool calls; each call ID receives exactly one result before the next model turn. Invalid, truncated, failed, or refused responses must not execute partial calls. A Chat Completions `[DONE]` sentinel without a preceding valid `finish_reason` is truncated, not successful; a `stop` finish reason with tool calls must also fail before any tool executes. Bound tool turns, network requests, stream frames, shell runtime and tool output. Streaming can emit partial text before a terminal error; never persist that partial text as a completed assistant turn.
- OAuth authorization uses a cryptographically random PKCE verifier/state, exact redirect path and state validation, bounded loopback callbacks and explicit user sign-in. Store access/refresh tokens in a private, bounded, atomically replaced credential file; never put them in a journal, command line or diagnostic. Refresh before expiry while locking read-refresh-write against other processes. A login is not working provider inference until its distinct wire transport sends a real authenticated request and handles tool results correctly.
- OpenAI Responses, native Ollama and direct Gemini have their own request/response and streaming adapters. SSE and Ollama NDJSON parsing are bounded independently. Gemini model-issued `thoughtSignature` parts accompany the exact native function call and must survive streamed/buffered tool results and journal replay; verify signed parts against visible text, tool names, IDs and arguments. Reject unsigned Gemini tool requests for every model ID, mismatched native history, or cross-model continuation rather than guessing model families or fabricating a signature. Older unsigned Gemini tool calls are therefore unavailable; text-only responses remain supported. Anthropic OAuth may target only its registered HTTPS inference endpoint, with refresh under the credential-store lock. Local fixture verification is not proof of live provider entitlement.
- Codex subscription inference is **not** public OpenAI Responses: use its account-scoped `/codex/responses` endpoint, bearer/JWT account and residency headers, mandatory streaming envelope and native encrypted reasoning replay. Persist opaque provider state only in the private journal; reject a different model, tampered visible text/tool calls or unsupported native output before replay, and omit provider state from foreign wire requests. OpenRouter alone does not echo authorization state: its browser grant uses a random PKCE verifier and a fixed loopback callback, then stores the exchanged key, not a renewable token. Do not disable state checks for standard OAuth providers. Personal GitHub Copilot uses a GitHub HTTPS device grant and pinned public Chat endpoint; let its account listing and the service decide available Chat model IDs rather than shipping a frozen allowlist, and do not claim Enterprise or non-Chat routes without implementing them.
- Authenticated model discovery is independent of wire routing. `--models` and background `/model`/setup/settings pickers may query only pinned provider listing endpoints or local Ollama tags; never forward a private API key or OAuth token to a caller-chosen host or follow listing redirects. Parse each account's complete bounded listing, including Anthropic cursor pages, before showing choices; refuse malformed, repeated, missing or oversized pages rather than treating partial discovery as global truth. No selectable model IDs or implicit model defaults may be hardcoded. When discovery fails, show its error and accept an explicitly typed ID without claiming entitlement. Network lookup must not block input; cancel and reap its subprocess when the chooser exits.
- Mobile specialization starts with repository inspection, then identifies Swift/Xcode/SwiftPM, Android/Gradle, Flutter or React Native from actual manifests. Never assume SDKs, simulators, signing keys or deployment permission. Follow local conventions and prefer focused builds/tests.
- File tools resolve paths under the selected workspace, reject traversal and symlink escapes, bound reads/searches, and perform exact-match edits. Replacements must not silently target ambiguous spans. Atomic writes must keep the original on failure.
- Shell execution is disabled by default. `--allow-shell` advertises shell commands but still requires explicit interactive approval for **each** command; noninteractive sessions deny execution. Commands are **not** sandboxed. Device deployment, signing, destructive and credential operations require informed approval of that exact command.
- API keys come from environment variables, not checked-in configuration or subprocess arguments. Opt-in sessions are private, append-only JSONL journals with stable parent-linked message IDs; branching retains prior messages, while forking creates a separate file containing the selected path. Existing flat JSON-array sessions migrate without dropping messages. Each message is durable before the agent advances; on restart unresolved tool calls receive recorded failure results and are never automatically re-executed. A stale writer must fail rather than overwrite another session update. Session files can contain source and credentials surfaced by tools; do not commit them.
- Model selection is a parent-linked journal metadata entry separate from provider messages. Keep provider/model ID only; never journal API keys, OAuth grants or custom endpoints. On `/resume`, `--session` and `/branch`, resolve the selected ancestry's current model against the registered route before changing TUI status; explicit CLI provider/model/API/endpoint overrides win. Preserve old journals without metadata, keep previews bounded past metadata to the first user prompt, and keep model markers out of replay, compaction and visible conversation.
- User/project `settings.json` loads typed defaults with explicit CLI > project > user precedence and diagnostics for invalid files; a shell-disable policy in either file denies `--allow-shell` instead of silently granting it. Project settings writes use private, atomic replacements under a lock. User and ancestor `AGENTS.md` load below mobile safety, with bounded imports confined to their source directory. Path-scoped `.pave/rules` must resolve and enter the next model system context before a model-requested file edit/write is allowed; journal the first withheld call as unexecuted and fail closed on unsafe scopes. Project/system prompt sources are not higher-priority safety rules: optional user/project `SYSTEM.md`, `SYSTEM_TEMPLATE.md` (strict `{{root}}` interpolation only) and `APPEND_SYSTEM.md` have explicit CLI > project > user precedence, bounded UTF-8 regular-file reads and no promotion from tool results. A custom override cannot remove the mobile safety prompt or ancestor `AGENTS.md`.
- The first-run wizard is gated to an interactive terminal with no explicit provider/model/session and no usable configured default. Persist only a versioned, user-scoped completion/skip marker and selected user model through owned, atomic config files; project policy and explicit CLI selection still win. Skipping an unset API key may save a model but must say prompts need the key; never solicit or render secret key text in TUI. OAuth sign-in uses the existing real handoff. `/setup` reopens the wizard; headless output remains untouched.
- Onboarding stage explanations belong to the chooser's transient presentation, not the transcript or persisted state. Give wide terminals concise step labels and keyboard guidance without reducing the searchable choice list below a usable page; narrow terminals omit explanatory rows. Resizing or typing a filter must not change the selected provider/model.
- Reuse the same cancellable, account-scoped model picker for setup, settings and `/model` rather than diverging discoverers. Discovery must call pinned provider listing endpoints only, never an override URL with an OAuth token; preserve supported wire-route validation before selection and put wizard navigation controls after live candidates without labeling controls as model IDs. Newly verified models may become the first choice only while the user has not navigated or filtered; preserve an explicit user selection on subsequent updates.
- Manual compaction appends a summary and first-kept user entry ID to the same journal; it never rewrites historical entries. Rebuilt model context uses the latest compaction on the selected ancestry path, then the kept turn and later messages. Do not compact unresolved tool calls; provider failure leaves the original model context and journal unchanged. Distinguish a summary of prior work from actual tool results.
- The TUI edits Unicode grapheme clusters, renders by terminal cell width, preserves UTF-8 codepoints across terminal reads and replaces malformed input. Keep keyboard/status/error feedback visible, limit in-memory transcript to the most recent 10,000 rows and draft bytes, coalesce queued keypress repaints, redraw only changed rows, and block without idle polling. While a turn is active, an input-select timeout may advance the elapsed header once per second even in the command picker or shell approval; keep the timer tied to the turn rather than resetting it on phase changes, and remove the timeout when idle. Model turns run on a cancellable worker that queues UI events and wakes the terminal by pipe; only the UI thread paints or confirms shell commands. Send typed model/tool phase notices through the same worker queue rather than guessing progress from transcript strings; mark a tool active only when execution begins, return to model status for a follow-up request and clear activity on completion/cancel/error. Keep submitted follow-ups out of the transcript until their turn starts, retract provisional text on cancellation/error, and settle every journaled tool call even if a command is interrupted. Support resize and multiline paste; preserve non-TTY output and reject shell approvals when the command cannot fit in the visible confirmation.
- `Composer` owns bounded grapheme edits, atomic pasted edits, undo/redo and kill/yank; `Transcript_view` owns sanitized semantic rows, stream rollback, tool settlement/expansion and lazy viewport snapshots. `Tui` alone maps terminal keys to these components and repaints changed rows. The CLI renders known typed failure messages once, without OCaml constructor noise; unknown exceptions retain their diagnostic text, and failed provisional text is rolled back before the error block. Do not persist presentation rows or forge provider usage from UI state. Use terminal-safe shortcuts (`Alt+O`, not macOS PTY's intercepted `Ctrl+O`); `NO_COLOR`, narrow widths and session restoration must remain legible.
- `Session_store` creates private journals only on explicit `/new`, indexed by canonical workspace path in the user state directory. `/resume` lists/reopens only same-workspace private owned regular files, with bounded previews and a nondestructive confirmation before switching away from unsaved history. Explicit `--session` paths retain the journal API's existing behavior. Every `/resume`, `/branch` and `/fork` transition repaints authoritative `Session.history` rather than leaving obsolete UI rows; none may overwrite an unsent editor draft.
- `Session_tree` presents at most 1,024 parent-linked journal entries and bounded, sanitized message previews; retain each full entry ID, including branch-point markers, as a valid branch target and show older ancestry remains reachable through `/branch ID`. Build picker labels without persisting them. A canceled tree picker must not alter the journal or editor; a confirmed selection uses the same authoritative history repaint as manual branching.
- Render the Pave mark as static ASCII only in the empty interactive transcript viewport; derive its pixel silhouette from `assets/pave-mark.svg`, center it without touching the journal, and use a compact label when the viewport is too small. Any transcript content replaces the illustration; non-TTY output remains unchanged.
- Inline slash suggestions derive names, arguments and descriptions from the same typed command catalog as `/help`. Treat them as ephemeral composer UI, never journal rows; bound their height, retain the draft on Escape, and insert selected commands without executing on the selection key. Only a subsequent submission may invoke a command. Preserve terminal fallback readability at 30×10 and in `NO_COLOR`.
- Interactive slash commands parse through `Interaction.commands`, a typed catalog shared by `/help` and the `/` + Tab searchable chooser. A chooser selection inserts a command into the existing draft; Escape must not submit or erase it. Distinguish static command choices from asynchronously verified `/model` candidates even when a worker wake pipe is active. Unknown slash forms must not reach a provider. `/login` reuses the CLI credential-store flow, releases the terminal from raw/alternate-screen mode while printing a browser URL or GitHub device verification code and awaiting authorization, then restores the same transcript/editor even on errors. Provider/model selection is explicit, recomputes the registered wire route, clears stale endpoint overrides and rebuilds the agent from journal or in-memory history. Do not require credentials before entering the interactive UI, but resolve them before appending a new prompt. Strip opaque Codex or Gemini continuation when the new model or protocol differs, while retaining visible messages.
- `/tools` must inspect the exact `Tools.available ~allow_shell` definitions passed to provider requests, not advertise shell tools that the agent filters out. Show the tool list compactly and details on demand; exposing `run_command` never removes its interactive approval or makes it sandboxed.
- `/context` reads authoritative journal ancestry and active route only while idle; name recorded conversation counts. Native Ollama may report nonnegative prompt/completion counts in a complete buffered response or final streamed frame; OpenAI Responses may report nonnegative `usage.input_tokens`/`output_tokens` in a valid completed response or `response.completed` event. Account-scoped Codex Responses uses the same nonnegative field names only from its own fully validated `response.completed` envelope, without treating its subscription as a priced public OpenAI request. Anthropic Messages' total input is `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`; use only complete nonnegative buffered usage or message-start input plus final message-delta output after `message_stop`, never the message-start output placeholder. Google Gemini `promptTokenCount` already includes cached input, while output is `candidatesTokenCount + thoughtsTokenCount`; accept nonnegative complete counts only after a valid buffered completion or a finished stream's final candidate/usage-only frame. Chat Completions can report nonnegative `usage.prompt_tokens`/`completion_tokens` after a valid buffered or finished streamed assistant reply; ignore partial/missing counters and early usage-only frames. Request `stream_options.include_usage` only at the pinned official OpenAI Chat endpoint; compatible gateways and Copilot must not receive an unsupported flag, but their complete reported usage can be recorded. Persist actual counts with the provider/model as private branch-local usage markers, separate from model context and visible message totals. Include successful compaction requests and ephemeral conversations. Never infer totals from text or partial frames, count abandoned ancestry, estimate usable context window/subscription cost, or claim unsupported routes supplied usage. A successful provider response can record real usage even if its summary is rejected as an invalid compaction result.
- `/usage` groups only provider-reported markers on the selected journal ancestry by actual provider/model; untracked provider requests cannot be estimated from the visible conversation. An ephemeral conversation may show a combined measured total without claiming durable per-model provenance; keep the missing-context-limit/cost disclaimer visible in both cases. The idle TUI header may show a cached branch-local or cumulative ephemeral input/output badge only when actual reported totals exist; refresh it on turn completion, branch checkout, resume, fork and startup, not on every keystroke. Hide it while working or on very narrow terminals so activity and model remain readable. No model requests or disk writes occur when inspecting usage.
- `/retry` is an idle-only model request, not a replay of tools. Accept only the most recent user turn when all subsequent messages are assistant-only without tool calls/results; refuse saved sessions without a predecessor entry or with model/compaction changes after that turn. Branch saved journals to the exact prior entry before resubmitting, retaining the previous answer off-branch; discard only the last unsaved ephemeral answer while keeping earlier history. Repaint authoritative history without replacing an unsent draft; the worker owns the reissued prompt. Ephemeral usage includes both billed responses, whereas saved `/usage` deliberately counts only selected ancestry.
- `Tui.hotkeys` is the single keyboard-help list used by `/help` and `/hotkeys`; compare it with the actual `Tui.read` bindings rather than inventing shortcuts. Headless help may list slash commands but must not advertise raw terminal hotkeys as if redirected stdin handled them.
- Informational transcript commands replace obsolete one-line footer alerts with normal keyboard hints; a previous `/resume` or branch status must not remain the active footer after `/context`, `/help` or `/hotkeys`. Do not clear active worker state or submitted transcript rows just to refresh the footer.
- Release archives must contain the native executable plus MIT and linked-library notices. The installer must verify the published SHA-256 checksum and archive contents before atomically replacing a binary; unsupported platforms and missing releases fail closed. Published documents and history must not retain legacy branding; legally required copyright and permission notices remain.
- Native self-update belongs only to a binary installed by the release installer, never an opam/foreign package. Embed that installer from the checked-in `install.sh` at build time; do not download and execute a fresh shell script. Find the running binary's install directory, require the native-install marker, ignore inherited update destination/version overrides, and retain HTTPS-only fetch, four-entry SHA-256 manifest, exact regular archive members and staged atomic binary rename. The marker is an install-layout hint, not an authentication signature.
- Release builds embed their validated tag into the binary from the release workflow, while source builds report no release version. `pave update --check` compares that tag against bounded HTTPS release metadata without changing installed files; errors must not become false “up-to-date” reports. Provider wire routes may be pinned, but model IDs, suggested lists and default model choices must come only from provider discovery or explicit user/session configuration.
- CLI and tests must exercise real HTTP completion/tool-call behavior, not just schema wiring. Keep domain modules small and keep provider-specific wire handling outside the tool loop.
