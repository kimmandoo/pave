# Pave design rules

The product goal is a maintainable OCaml mobile coding agent. The planned feature set is not yet complete. Implement and verify each vertical capability before exposing it; never advertise unfinished catalog, LSP/DAP, subagent, extension or tool features as working.

- Provider identity, model routing, credential selection and wire serialization are separate contracts. A provider descriptor selects one supported API family and endpoint for a model; it must not send a foreign protocol through the Chat Completions adapter as a fallback. OpenAI Chat Completions and Anthropic Messages use distinct request/response wire adapters and a shared bounded SSE frame parser. A model turn produces either an assistant answer or tool calls; each call ID receives exactly one result before the next model turn. Invalid, truncated, failed, or refused responses must not execute partial calls. A Chat Completions `[DONE]` sentinel without a preceding valid `finish_reason` is truncated, not successful; a `stop` finish reason with tool calls must also fail before any tool executes. Bound tool turns, network requests, stream frames, shell runtime and tool output. Streaming can emit partial text before a terminal error; never persist that partial text as a completed assistant turn.
- OAuth authorization uses a cryptographically random PKCE verifier/state, exact redirect path and state validation, bounded loopback callbacks and explicit user sign-in. Store access/refresh tokens in a private, bounded, atomically replaced credential file; never put them in a journal, command line or diagnostic. Refresh before expiry while locking read-refresh-write against other processes. A login is not working provider inference until its distinct wire transport sends a real authenticated request and handles tool results correctly.
- The OAuth store separates the provider-reported account ID from the account selector. Preserve provider IDs unchanged for wire headers; when no provider ID exists, assign a cryptographically random `pave-local:<hex>` selector scoped to the local store. Sort selectors deterministically, require explicit selection when multiple grants exist, and permit multiple accountless grants without inventing provider identity. Migrate older store versions under the same lock and retain provider/grant/registered-route binding.
- Resolve provider, grant, account selector, credential kind (API key, bound OAuth grant or cloud identity) and registered endpoint before any authenticated HTTP request; reject mismatches without sending credentials. Keep Vertex ADC and Bedrock AWS credentials separate from API-key and OAuth tokens. An environment API key visibly takes precedence over a saved grant; never offer a key text editor without a separately designed private lifecycle.
- `--mask-secrets` is opt-in local exact-value redaction for the active provider API key and OAuth access token. Use collision-safe reversible placeholders for tool arguments before execution, and one-way redaction for UI/event output; do not claim to cover images, opaque state, ambient identities, transformed or unknown values, or previously persisted journal content. It is not encryption and does not control provider retention.
- Keep OAuth tokens in the private local store unless a real deployable remote broker and explicit trust model exist; do not substitute an imaginary hosted service.
- Apple Foundation Models is an on-device, text-only route available only when the macOS arm64 helper is packaged or installed. Expose only the OS-managed `default` selector, not a fabricated remote model roster; verify runtime availability before generation, never invent a credential, and do not expose Pave workspace tools or claim file, shell, or network access. Reject unsupported media and show the specific macOS/Apple Intelligence readiness requirement.
- OpenAI Responses, native Ollama and direct Gemini have their own request/response and streaming adapters. SSE and Ollama NDJSON parsing are bounded independently. Gemini model-issued `thoughtSignature` parts accompany the exact native function call and must survive streamed/buffered tool results and journal replay; verify signed parts against visible text, tool names, IDs and arguments. Reject unsigned Gemini tool requests for every model ID, mismatched native history, or cross-model continuation rather than guessing model families or fabricating a signature. Older unsigned Gemini tool calls are therefore unavailable; text-only responses remain supported. Anthropic OAuth may target only its registered HTTPS inference endpoint, with refresh under the credential-store lock. Local fixture verification is not proof of live provider entitlement.
- Codex subscription inference is **not** public OpenAI Responses: use its account-scoped `/codex/responses` endpoint, bearer/JWT account and residency headers, mandatory streaming envelope and native encrypted reasoning replay. Persist opaque provider state only in the private journal; reject a different model, tampered visible text/tool calls or unsupported native output before replay, and omit provider state from foreign wire requests. OpenRouter alone does not echo authorization state: its browser grant uses a random PKCE verifier and a fixed loopback callback, then stores the exchanged key, not a renewable token. Do not disable state checks for standard OAuth providers. Personal GitHub Copilot uses a GitHub HTTPS device grant and pinned public Chat endpoint; let its account listing and the service decide available Chat model IDs rather than shipping a frozen allowlist, and do not claim Enterprise or non-Chat routes without implementing them.
- OpenAI Codex browser PKCE and device approval share the same account identity and pinned Responses route; preserve the stored grant kind across locked refresh. Device approval uses a fixed verification URL, bounded polling and the pinned authorization-code exchange, without a loopback callback or weakened provider/account/route binding.
- Authenticated model discovery is independent of wire routing. A model identity is the exact tuple `(provider, optional account ID, registered route, upstream ID)`; upstream IDs may contain slashes, and display labels are presentation-only. `--models` and background `/model`/setup/settings pickers may query only pinned provider listing endpoints or local Ollama tags; never forward a private API key or OAuth token to a caller-chosen host or follow listing redirects. Parse each account's complete bounded listing, including Anthropic cursor pages, before showing choices; refuse malformed pages, repeated cursors, duplicate IDs, missing pages or oversized pages rather than treating partial discovery as global truth. Fetch a fresh listing on every picker open; do not cache model rosters. Keep model-ID provenance separate from capability provenance; optional provider-reported capabilities retain their source and retrieval time, and absent values remain unknown. Listing membership alone never proves route, tool, context, or entitlement support. No selectable model IDs or implicit model defaults may be hardcoded. When discovery fails, show its error and accept an explicitly typed ID without claiming entitlement. Network lookup must not block input; cancel and reap its subprocess when the chooser exits.
- Mobile specialization starts with repository inspection, then identifies Swift/Xcode/SwiftPM, Android/Gradle, Flutter or React Native from actual manifests. Never assume SDKs, simulators, signing keys or deployment permission. Follow local conventions and prefer focused builds/tests.
- File tools resolve paths under the selected workspace, reject traversal and symlink escapes, bound reads/searches, and perform exact-match edits. Replacements must not silently target ambiguous spans. Atomic writes must keep the original on failure.
- Shell execution is disabled by default. `--allow-shell` advertises shell commands but still requires explicit interactive approval for **each** command; noninteractive sessions deny execution. Commands are **not** sandboxed. Device deployment, signing, destructive and credential operations require informed approval of that exact command.
- Opt-in sessions are private, append-only JSONL journals with stable parent-linked message IDs; branching retains prior messages, while forking creates a separate file containing the selected path. Existing flat JSON-array sessions migrate without dropping messages. Persist each assistant tool-call message before execution, fsync start before invoking a tool, and persist terminal settle/abort state before its provider result. Session-exit markers retain unresolved call IDs, names and known execution states without duplicating tool arguments. On restart, pair every unfinished call with exactly one conservative provider-valid tool result and never rerun calls whose side effects are unknown or may have occurred. Lifecycle and exit metadata remain branch-local and out of model context. A stale writer must fail rather than overwrite another session update. Session files can contain source and credentials surfaced by tools; do not commit them.
- Model selection is a parent-linked journal metadata entry separate from provider messages. Persist the canonical provider/account/route/upstream-ID identity; custom identities also carry an opaque configuration digest so edits to a route fail closed. Keep display labels separate, and never journal API keys, OAuth grants or custom endpoint values. On `/resume`, `--session` and `/branch`, resolve the selected ancestry's current identity against the registered route before changing TUI status; explicit CLI provider/model/API/endpoint overrides win. Preserve old journals without metadata, keep previews bounded past metadata to the first user prompt, and keep model markers out of replay, compaction and visible conversation.
- Persist thinking metadata, disabled tools, approval mode and entry labels as typed parent-linked journal entries, not provider messages; they follow the selected ancestry. Provider/model/API entries remain separate route metadata. Titles and pin changes are session-global journal metadata; the private recent-list pin index is only a projection. `/thinking` records branch-local metadata; adapters translate only documented provider controls, leave unsupported routes unchanged, and preserve opaque reasoning only for a matching provider/route/model. Fireworks reasoning effort and Alibaba's explicit boolean Qwen control do not imply that an arbitrary model supports thinking. Store user-image attachments as bounded top-level journal metadata, strip their bytes from the nested provider-message record, never send filenames, and reject unsupported routes before credential or network work; previews expose names/MIME labels only.
- User/project `settings.json` loads typed defaults with explicit CLI > project > user precedence and diagnostics for invalid files; a shell-disable policy in either file denies `--allow-shell` instead of silently granting it. Project settings writes use private, atomic replacements under a lock. User and ancestor `AGENTS.md` load below mobile safety, with bounded imports confined to their source directory. Path-scoped `.pave/rules` must resolve and enter the next model system context before a model-requested file edit/write is allowed; journal the first withheld call as unexecuted and fail closed on unsafe scopes. Project/system prompt sources are not higher-priority safety rules: optional user/project `SYSTEM.md`, `SYSTEM_TEMPLATE.md` (strict `{{root}}` interpolation only) and `APPEND_SYSTEM.md` have explicit CLI > project > user precedence, bounded UTF-8 regular-file reads and no promotion from tool results. A custom override cannot remove the mobile safety prompt or ancestor `AGENTS.md`.
- Tool approval modes are `always-ask` (prompt for writes and execution), `write` (allow reads/writes, prompt for execution) and `yolo` (allow all ordinary tool tiers); typed per-tool policies and command patterns refine the mode, with deny winning across user/project scopes. `run_command` still requires Pave's interactive per-command prompt under every mode and per-tool allow; headless prompt-required calls fail closed. Approval previews identify the tool, tier, impact and arguments, and explicitly disclose that shell commands run unsandboxed. Command-pattern allow rules match only one simple command; deny and prompt rules inspect compound subcommands so an allowed prefix cannot mask a denied later command.
- A visible approval preview must fit above the composer, active row and shortcut overlay before `y` can authorize an effect. If resizing clips a pending preview, show a short resize hint, retain the pending choice and deny `y` until the full preview fits again; other keys may deny immediately. Never treat a clipped preview as informed consent.
- The first-run wizard is gated to an interactive terminal with no explicit provider/model/session and no usable configured default. Persist only a versioned, user-scoped completion/skip marker and selected user model through owned, atomic config files; project policy and explicit CLI selection still win. Skipping an unset API key may save a model but must say prompts need the key; never solicit or render secret key text in TUI. OAuth sign-in uses the existing real handoff. `/setup` reopens the wizard; headless output remains untouched.
- Onboarding stage explanations belong to the chooser's transient presentation, not the transcript or persisted state. Give wide terminals concise step labels and keyboard guidance without reducing the searchable choice list below a usable page; narrow terminals omit explanatory rows. Resizing or typing a filter must not change the selected provider/model.
- Reuse the same cancellable, account-scoped model picker for setup, settings and `/model` rather than diverging discoverers. A bounded coordinator snapshots each provider/account/route independently as loading, ready, unsupported or failed; partial success remains usable, and unavailable states appear in status rather than as selectable models. Fetch fresh listings on every open with no roster cache. Discovery must call pinned provider listing endpoints only, never an override URL with an OAuth token; preserve supported wire-route validation before selection and put wizard navigation controls after live candidates without labeling controls as model IDs. Newly available models may become the first choice only while the user has not navigated or filtered; preserve an explicit user selection on subsequent updates. Each open picker exclusively owns keyboard input, including Ctrl+C; cancellation closes only that picker, leaves the composer and selected model/default unchanged, and stops any cancellable discovery worker. Account handoff owns terminal input until return; discard pending type-ahead before restoring TUI focus.
- `/model` and the shared setup/settings model picker show only fresh, selectable model IDs for the chosen credential/account and registered API route; do not mingle static suggestions, arbitrary typed IDs, unclassified route claims, public catalogs without required inference credentials, unverified OS-managed defaults, unavailable provider routes, or route-browse commands with model candidates. An empty or failed listing stays empty and explains why; setup navigation remains a separate control. Preserve explicit CLI/session selectors for users who already know an unlisted model ID. A successful listing and local credential do not prove remote inference entitlement: do not label a model as permission-verified without a provider guarantee. Limit discovery workers, bound each request and avoid redundant unauthenticated traffic; maintain cancellation and account identity.
- Set `--context-window TOKENS` only for the exact initial provider/model/API/endpoint. `auto` may consume only a fresh pinned listing's raw positive limit for the exact model: Command Code `context_length` plus its advertised API route, Google `inputTokenLimit`, account-scoped Codex `context_window`, Devin Connect `maxTokens`, OpenRouter account `/models/user` `context_length` through its single registered Chat route, or Anthropic `max_input_tokens` on its sole direct Messages route. Preserve OpenRouter `top_provider.max_completion_tokens` only as provider-reported output metadata; it does not replace the context window, but caps the byte-proxy output reserve when lower than its default. Anthropic native compaction additionally requires explicit true `capabilities.compaction.supported` and `capabilities.compaction.summarize.supported`, official `api.anthropic.com/v1/messages`, and API-key auth; replay the exact signed block only on that route/model and include the beta header. Listings without per-model route claims are accepted only for these providers' single registered route; a nonregistered endpoint override fails closed. Never infer limits from model names or apply family fallbacks. Devin `tokenizerType` is display-only metadata; local budgeting remains a conservative UTF-8 byte proxy, not provider tokenization. `/context` names the source and distinguishes window/output reserve from the proxy; count media payload bytes in the proxy while leaving media token costs unknown. Before each request, trim oversized text tool results only in provider-facing copies, then summarize older complete turns in bounded chunks if needed. Preserve the latest user turn and attachments, tool-call/result adjacency, signed provider replay where valid, and immutable journal history. Persist a branch-local compaction marker only after all summaries succeed; generic summarization must fail closed rather than discard signed state valid for the active route. Direct OpenAI Responses and capability-advertised Anthropic Messages are the only native compaction routes.
- The TUI edits Unicode grapheme clusters, renders by terminal cell width, preserves UTF-8 codepoints across terminal reads and replaces malformed input. Keep keyboard/status/error feedback visible, limit in-memory transcript to the most recent 10,000 rows and draft bytes, coalesce queued keypress repaints, redraw only changed rows, and block without idle polling. While a turn is active, render a high-contrast activity row immediately above the editor/footer with a spinner, typed model/tool phase and elapsed time; keep its timer tied to the turn rather than resetting it on phase changes, including in pickers and shell approval, and remove it when idle. Never display private model chain-of-thought as activity. Model turns run on a cancellable worker that queues UI events and wakes the terminal by pipe; only the UI thread paints or confirms shell commands. Each notice carries its turn ID and is accepted only from that turn's worker thread; ignore stale notices/completions after handoff. Serialize cancellation against completion: a cancellation that wins before a normal completion is enqueued must produce `Cancelled`, and deliver one terminal outcome so the UI can settle its owner. Once cancellation is requested, discard queued message/delta/phase notices for that turn while still delivering its terminal completion. Send typed model/tool phase notices through the same worker queue rather than guessing progress from transcript strings; mark a tool active only when execution begins, return to model status for a follow-up request and clear activity on completion/cancel/error. Keep submitted follow-ups out of the transcript until their turn starts, retract provisional text on cancellation/error, and settle every journaled tool call even if a command is interrupted. Support resize and multiline paste; preserve non-TTY output and reject shell approvals when the command cannot fit in the visible confirmation.
- Route terminal input, resize, runner/listing/approval/background results and shutdown through one typed TUI queue drained on the UI thread. Publish under the queue lock and wake on empty-to-nonempty transitions; never lose a wake or duplicate a submission. Normalize physical CR/LF as Return, disable terminal ICRNL/INLCR/IGNCR while raw so pasted CRLF remains one draft newline, and never execute bracket-pasted commands or approvals. Restore terminal modes and prior signal handlers before exiting on INT, HUP, QUIT, TERM or TSTP; use `128 + POSIX signal number` for signal exits.
- The turn runner exposes owner-tagged `Turn_started`, `Transcript_message`, `Text_delta`, `Activity_phase`, `Tool_event`, `Turn_completed`, `Turn_cancelled` and `Turn_failed` events through one typed callback. A `Tool_event` carries the provider call ID and a start/update/settle/abort outcome; start/update notices obey the owning worker-thread and cancellation gates, while settle/abort results remain deliverable after cancellation. `Turn_started` is emitted on the UI caller; worker notices and terminal outcomes are drained on the UI thread. Shell approvals remain turn-owned requests dispatched on that thread.
- `Composer` owns bounded grapheme edits, atomic pasted edits, undo/redo and kill/yank; `Transcript_view` owns sanitized semantic rows, stream rollback, per-call tool settlement/expansion and lazy viewport snapshots. `Tui` maps typed tool lifecycle events to call-owned transcript groups; `run_command` progress reports cumulative received-byte counts only, never intermediate output content. `Tui` alone maps terminal keys to these components and repaints changed rows. The CLI renders known typed failure messages once, without OCaml constructor noise; unknown exceptions retain their diagnostic text, and failed provisional text is rolled back before the error block. Do not persist presentation rows or forge provider usage from UI state. Use terminal-safe shortcuts (`Alt+O`, not macOS PTY's intercepted `Ctrl+O`); `NO_COLOR`, narrow widths and session restoration must remain legible.
- Keep the visible active row to its typed model/tool phase and elapsed time; `Tool_updated` byte counts must not displace it. Wrap prose at whitespace when possible and hard-wrap only an unbroken token at grapheme boundaries, preserving the original text.
- Keep ordinary conversation prose visually continuous: use compact role labels and modest indentation instead of repeated tree-connector gutters. Preserve clear role labels and explicit start/result boundaries for tool activity.
- `Session_store` creates private journals only on explicit `/new`, indexed by canonical workspace path in the user state directory. `/resume` lists/reopens only same-workspace private owned regular files, with bounded previews and a nondestructive confirmation before switching away from unsaved history. Explicit `--session` paths retain the journal API's existing behavior. Every `/resume`, `/branch` and `/fork` transition repaints authoritative `Session.history` rather than leaving obsolete UI rows; none may overwrite an unsent editor draft.
- `/clear` appends a reset boundary without deleting journal history, model/settings metadata or reported usage, and refuses while tool calls are unresolved. `/fresh` rebuilds local agent state from the current conversation context without journal mutation. Switching away prompts before discarding an unsaved conversation or staged media; cancellation preserves the draft and attachments.

- `Session_tree` presents at most 1,024 parent-linked journal entries and bounded, sanitized message previews; retain each full entry ID, including branch-point markers, as a valid branch target and show older ancestry remains reachable through `/branch ID`. Build picker labels without persisting them. A canceled tree picker must not alter the journal or editor; a confirmed selection uses the same authoritative history repaint as manual branching.
- Render the Pave mark as static ASCII only in the empty interactive transcript viewport; derive its pixel silhouette from `assets/pave-mark.svg`, center it without touching the journal, and use a compact label when the viewport is too small. Any transcript content replaces the illustration; non-TTY output remains unchanged.
- Inline slash suggestions derive names, arguments and descriptions from the same typed command catalog as `/help`. Treat them as ephemeral composer UI, never journal rows; bound their height and retain the draft on Escape. Tab or Enter on a partial suggestion inserts without executing; Enter on an exact command draft submits it. An inserted choice still needs a separate submit. Preserve terminal fallback readability at 30×10 and in `NO_COLOR`.
- Interactive slash commands parse through `Interaction.commands`, a typed catalog shared by `/help` and the `/` + Tab searchable chooser. A chooser selection inserts a command into the existing draft; Escape must not submit or erase it. Distinguish static command choices from asynchronously verified `/model` candidates even when a worker wake pipe is active. Unknown slash forms must not reach a provider. `/login` reuses the CLI credential-store flow, releases the terminal from raw/alternate-screen mode while printing a browser URL or GitHub device verification code and awaiting authorization, then restores the same transcript/editor even on errors. Provider/model selection is explicit, recomputes the registered wire route, clears stale endpoint overrides and rebuilds the agent from journal or in-memory history. Do not require credentials before entering the interactive UI, but resolve them before appending a new prompt. Strip opaque Codex or Gemini continuation when the new model or protocol differs, while retaining visible messages.
- `/tools` must inspect the exact `Tools.available ~allow_shell` definitions passed to provider requests, not advertise shell tools that the agent filters out. Show the tool list compactly and details on demand; exposing `run_command` never removes its interactive approval or makes it sandboxed.
- `Agent` rebuilds provider tool definitions from the current availability predicate for every model request and rechecks it before dispatch; predicate failures must never grant a disabled capability. Validate each argument object against the advertised function schema, including required fields, allowed property names, types, integer bounds and duplicate-key rejection, before any approval prompt or tool invocation. Preserve one ordered provider result for every model call ID, including invalid or dynamically unavailable calls.
- `Tools.execution_mode` classifies only `mobile_project`, `read_file`, `workspace_snapshot`, `list_files`, `glob`, `search`, `grep`, `token_count` and `repository_security_scan` as shared; mutations, `run_command` and unknown names remain exclusive. Preflight, lifecycle/progress callbacks and ordered result settlement run on the Agent owner thread; at most four contiguous shared calls execute concurrently, and exclusive work waits for the prior shared group to finish. Cancellation prevents not-yet-started calls from running while preserving ordered provider results. Structured text/image results must retain typed blocks through every provider adapter; never stringify image payloads.
- Tool results retain ordered canonical `Text`/`Image` content blocks in private JSONL history. Chat Completions emit text tool outputs and then one ordered user image group; Responses, Codex, Anthropic, Bedrock, Gemini and Ollama use native image fields. A transport without an image field rejects image-bearing history before authentication or network I/O rather than dropping it or exposing base64 as text. TUI, session-tree and `/entries` previews show `[MIME image]`, never image data.
- User image/audio/video attachments are workspace-relative, magic-checked and size-bounded private journal payloads. Direct Gemini GenerateContent and Vertex GenerateContent send supported MIME types as native `inlineData`; every other route rejects audio/video before authentication or network I/O rather than relabeling them as images. The byte proxy counts base64 payload bytes but never invents modality token costs; Google modality usage is surfaced only when response metadata reports it. Generic summaries retain attachment names/MIME but never mutate journal artifacts; newest-turn attachments and route-valid signed replay remain intact.
- `pave task` exposes only fixed, documented non-chat APIs behind real consumers; never advertise them as chat routes or infer task compatibility from a model name. Keep credentials bound to the registered provider host, requests and responses bounded and strictly validated, and cancellation effective. Media inputs must be workspace-relative, magic/MIME-checked and size-limited; generated files must remain workspace-relative, size-limited and no-overwrite. Do not offer video generation without a documented live API; OpenAI's retired Videos/Sora API has no documented replacement.

- `/context` reads authoritative journal ancestry and active route only while idle; name recorded conversation counts. Native Ollama may report nonnegative prompt/completion counts in a complete buffered response or final streamed frame; OpenAI Responses may report nonnegative `usage.input_tokens`/`output_tokens` in a valid completed response or `response.completed` event. Account-scoped Codex Responses uses the same nonnegative field names only from its own fully validated `response.completed` envelope, without treating its subscription as a priced public OpenAI request. Anthropic Messages' total input is `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`; use only complete nonnegative buffered usage or message-start input plus final message-delta output after `message_stop`, never the message-start output placeholder. Google Gemini `promptTokenCount` already includes cached input, while output is `candidatesTokenCount + thoughtsTokenCount`; accept nonnegative complete counts only after a valid buffered completion or a finished stream's final candidate/usage-only frame. Chat Completions can report nonnegative `usage.prompt_tokens`/`completion_tokens` after a valid buffered or finished streamed assistant reply; ignore partial/missing counters and early usage-only frames. Request `stream_options.include_usage` only at the pinned official OpenAI Chat endpoint; compatible gateways and Copilot must not receive an unsupported flag, but their complete reported usage can be recorded. Persist actual counts with the provider/model as private branch-local usage markers, separate from model context and visible message totals. Include successful compaction requests and ephemeral conversations. Never infer totals from text or partial frames, count abandoned ancestry, estimate usable context window/subscription cost, or claim unsupported routes supplied usage. A successful provider response can record real usage even if its summary is rejected as an invalid compaction result.
- Direct Anthropic Messages requests with an API key to `https://api.anthropic.com/v1/messages` send the documented top-level `cache_control: {"type":"ephemeral"}` automatic prompt cache; OAuth, compatible gateways and custom endpoints receive no cache directive. The cache has Anthropic's default five-minute lifetime and can have different billing and retention terms; users must review current provider terms. Record only provider-reported cache-read/write token counts and never estimate dollar cost.
- Completion transports classify HTTP authentication, permission, model/route, context-size, rate-limit and provider-unavailable failures. An HTTP 400 is a context failure only for a recognized provider error code. Timeouts distinguish failure before first response-body data from failure after data; an after-data timeout may be an idle or total-request limit. Never automatically replay a completion: remote acceptance/billing is ambiguous, and visible text or tool side effects must not be duplicated. `/retry` remains an explicit user action restricted to the safe tool-free boundary below.
- Persist token usage only after a validated completion and keep actual provider/account/model/API-route provenance with each saved marker. Cache, reasoning/thought and modality token counts remain optional provider-reported details; unknown counts and unreported premium usage remain unknown. Direct Gemini GenerateContent may retain `promptTokensDetails`, `cacheTokensDetails` and `candidatesTokensDetails` exactly by modality; these breakdowns do not become local tokenizer estimates. Account and route provenance do not provide a price table: Pave does not estimate provider cost or subscription value.
- `/usage` groups only provider-reported markers on the selected journal ancestry by actual provider/account/model/API route; untracked provider requests cannot be estimated from the visible conversation. An ephemeral conversation may show a combined measured total without claiming durable per-identity provenance; keep the missing-context-limit/cost disclaimer visible in both cases. The idle TUI header may show a cached branch-local or cumulative ephemeral input/output badge only when actual reported totals exist; refresh it on turn completion, branch checkout, resume, fork and startup, not on every keystroke. Hide it while working or on very narrow terminals so activity and model remain readable. No model requests or disk writes occur when inspecting usage.
- `/retry` is an idle-only model request, not a replay of tools. Accept only the most recent user turn when all subsequent messages are assistant-only without tool calls/results; refuse saved sessions without a predecessor entry or with model/compaction changes after that turn. Branch saved journals to the exact prior entry before resubmitting, retaining the previous answer off-branch; discard only the last unsaved ephemeral answer while keeping earlier history. Repaint authoritative history without replacing an unsent draft; the worker owns the reissued prompt. Ephemeral usage includes both billed responses, whereas saved `/usage` deliberately counts only selected ancestry.
- `Keybindings` is the conflict-checked source for action mapping, focus priority, allowed overrides and help; `/help` and `/hotkeys` derive raw-key guidance from the same table. Reject unknown targets and overrides that collide within a focus. Headless help may list slash commands but must not advertise raw terminal hotkeys as if redirected stdin handled them.
- Resolve input focus in this order: bracketed paste, top chooser/approval, search, hints, composer. Only the top overlay handles modal keys; approval accepts plain unpasted `y`/`Y` only while the complete preview fits. Resize and cancellation preserve the editor draft, and a paste cannot submit commands or approve effects.
- Steering and follow-ups have separate submission boundaries: while busy, plain Enter/Return cancels the active turn and queues steering ahead of FIFO follow-ups; Alt/Option+Enter/Return or `/queue MESSAGE` queues without interrupting. Alt/Option+Up dequeues the newest steering item first, otherwise the newest follow-up, and restores it ahead of the editor draft; if the bounded composer rejects the prepend, restore the queue item. Ctrl+C cancels the active turn without clearing an unsent draft; `/retry` remains restricted to safe tool-free turns.
- `/help`, `/hotkeys`, idle status and chooser hints use `Option`/`Return` on macOS and `Alt`/`Enter` elsewhere. Notty does not decode Kitty modified-Enter CSI-u sequences; support the ESC-prefixed Return forms and retain `/queue MESSAGE` as an explicit fallback rather than advertising unsupported Ctrl+Enter.
- Informational transcript commands replace obsolete one-line footer alerts with normal keyboard hints; a previous `/resume` or branch status must not remain the active footer after `/context`, `/help` or `/hotkeys`. Do not clear active worker state or submitted transcript rows just to refresh the footer.
- Release archives must contain only the native executable plus MIT and linked-library notices. Native executables must not retain build-time dependencies on non-system shared libraries (such as libzstd from the OCaml toolchain); each extracted target must be checked for runtime dependencies and launched in native CI. The installer must verify the published SHA-256 checksum and archive contents before atomically replacing a binary; unsupported platforms and missing releases fail closed. Published documents and history must not retain legacy branding; legally required copyright and permission notices remain.
- Native self-update belongs only to a binary installed by the release installer, never an opam/foreign package. Embed that installer from the checked-in `install.sh` at build time; do not download and execute a fresh shell script. Find the running binary's install directory, require the native-install marker, ignore inherited update destination/version overrides, and retain HTTPS-only fetch, four-entry SHA-256 manifest, exact regular archive members and staged atomic binary rename. The marker is an install-layout hint, not an authentication signature.
- Release builds embed their validated tag into the binary from the release workflow, while source builds report no release version. `pave update --check` compares that tag against bounded HTTPS release metadata without changing installed files; errors must not become false “up-to-date” reports. Provider wire routes may be pinned, but model IDs, suggested lists and default model choices must come only from provider discovery or explicit user/session configuration.
- CLI and tests must exercise real HTTP completion/tool-call behavior, not just schema wiring. Keep domain modules small and keep provider-specific wire handling outside the tool loop.
- Durable session artifacts and jobs are private and session-owned. Bound active jobs, result bytes, per-item and aggregate artifact storage; cancellation reports that provider usage may already have been charged. Journal each job start and deliver each terminal result idempotently to its owner. Child agents expose only bounded read-only tools and require explicit approval even in permissive modes. Plan, advisor, watchdog, loop and autoresearch workflows cannot edit or execute; persisted goals and interruption rules are branch-local guidance, not security controls.
- Managed process/PTY jobs and Git worktrees exist only in private saved sessions and are isolated by session owner. Bound process lifetime, job count and retained output; terminate owned process groups on cancellation and application shutdown. Starting a process/shell, writing or closing its stdin, killing it, and creating/committing/removing a worktree each require interactive approval even in permissive modes. A worktree URI resolves only through its owner record; commits stage only the explicitly listed paths and preserve unrelated staged changes.
- Workspace rewind snapshots successful `write_file`/`edit_file`/`apply_edits`/`ast_edit` and LSP `apply_preview` file changes only when the pre/post data fit the private 1 MiB capture limit. LSP rename/code-action responses are preview-only: cache the exact multi-file contents and hashes, then apply only the one-shot preview ID after separate approval displays every target path, source/result hash and complete proposed content. Require explicit restore approval and an exact current-content-and-mode match before restoring; preserve conflicting user changes. Changes in managed worktrees, shell commands, managed processes and Git/worktree operations are recorded as non-reversible; never replay or undo them.
- Managed child processes inherit only the explicit runtime/navigation allowlist by default; provider, OAuth, cloud and search credentials or arbitrary ambient variables never pass through implicitly. Explicit environment overrides remain visible in execution approval details.
- `workspace_eval` kernels are persistent only for their private session and are unsandboxed; every execution requires separate approval. The Python import allowlist and absence of a provided pip/npm installer are package policy, not a security boundary. The bridge exposes bounded read-only workspace tools and inspection of existing session-owned jobs; it cannot start or mutate jobs.
- LSP servers and DAP adapters are unsandboxed process boundaries. Starting them requires explicit approval; DAP launch, attach, breakpoints, execution control and evaluate require the corresponding effect approval. Read-only thread/frame/variable inspection does not grant debuggee control.
- `web_search` and `web_fetch` are separate network-trust boundaries and require explicit approval; disclose the destination/provider and never pass unrelated provider credentials. SSH uses system identities and verified `known_hosts`, is not authorized by local workspace access, and requires its own explicit connection and remote-operation approvals.
- `repository_security_scan` is a read-only deterministic scan, including hidden and gitignored credential files outside excluded dependency/VCS/build directories. Findings contain hashes and rule metadata, never matched secret values; SARIF includes validated rule-produced findings only and marks capped scans incomplete. Model-proposed findings remain untrusted.
- `fuzzy_file_search` matches Unicode-case-folded path subsequences, ranks file and directory candidates deterministically, and stays inside the checked workspace traversal. Hidden entries are excluded by default; `.gitignore`, symlink, dependency/build/VCS exclusions and traversal/result caps apply. Report truncation instead of presenting partial results as complete.
