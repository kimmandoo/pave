# Pave design rules

The product goal is a maintainable OCaml mobile coding agent. The planned feature set is not yet complete. Implement and verify each vertical capability before exposing it; never advertise unfinished catalog, LSP/DAP, subagent, extension or tool features as working.

- Provider identity, model routing, credential selection and wire serialization are separate contracts. A provider descriptor selects one supported API family and endpoint for a model; it must not send a foreign protocol through the Chat Completions adapter as a fallback. OpenAI Chat Completions and Anthropic Messages use distinct request/response wire adapters and a shared bounded SSE frame parser. A model turn produces either an assistant answer or tool calls; each call ID receives exactly one result before the next model turn. Invalid, truncated, failed, or refused responses must not execute partial calls. A Chat Completions `[DONE]` sentinel without a preceding valid `finish_reason` is truncated, not successful; a `stop` finish reason with tool calls must also fail before any tool executes. Bound tool turns, network requests, stream frames, shell runtime and tool output. Streaming can emit partial text before a terminal error; never persist that partial text as a completed assistant turn. A reply with neither text nor tool calls is reported to the user but not retained in history, because replay serializers reject empty assistant turns.
- OAuth authorization uses a cryptographically random PKCE verifier/state, exact redirect path and state validation, bounded loopback callbacks and explicit user sign-in. Store access/refresh tokens in a private, bounded, atomically replaced credential file; never put them in a journal, command line or diagnostic. Refresh before expiry while locking read-refresh-write against other processes. A login is not working provider inference until its distinct wire transport sends a real authenticated request and handles tool results correctly.
- The OAuth store separates the provider-reported account ID from the account selector. Preserve provider IDs unchanged for wire headers; when no provider ID exists, assign a cryptographically random `pave-local:<hex>` selector scoped to the local store. Sort selectors deterministically, require explicit selection when multiple grants exist, and permit multiple accountless grants without inventing provider identity. Migrate older store versions under the same lock and retain provider/grant/registered-route binding.
- Resolve an exact account-scoped selector or saved journal/workspace model identity before looking up a launch credential; infer the account only when one saved grant exists. When multiple grants remain for an unscoped model, an interactive prompt must select a grant before submission and persist that account with the model identity; cancelling restores the draft. Headless prompts must fail closed and require an account selector rather than choose a grant by ordering or model name.
- Resolve provider, grant, account selector, credential kind (API key, bound OAuth grant or cloud identity) and registered endpoint before any authenticated HTTP request; reject mismatches without sending credentials. Keep Vertex ADC and Bedrock AWS credentials separate from API-key and OAuth tokens. An environment API key visibly takes precedence over a saved grant; never offer a key text editor without a separately designed private lifecycle.
- `--mask-secrets` is opt-in local exact-value redaction for the active provider API key and OAuth access token. Use collision-safe reversible placeholders for tool arguments before execution, and one-way redaction for UI/event output; do not claim to cover images, opaque state, ambient identities, transformed or unknown values, or previously persisted journal content. It is not encryption and does not control provider retention.
- Keep OAuth tokens in the private local store unless a real deployable remote broker and explicit trust model exist; do not substitute an imaginary hosted service.
- Apple Foundation Models is an on-device, text-only route available only when the macOS arm64 helper is packaged or installed. Expose only the OS-managed `default` selector, not a fabricated remote model roster; verify runtime availability before generation, never invent a credential, and do not expose Pave workspace tools or claim file, shell, or network access. Reject unsupported media and show the specific macOS/Apple Intelligence readiness requirement.
- OpenAI Responses, native Ollama and direct Gemini have their own request/response and streaming adapters. SSE and Ollama NDJSON parsing are bounded independently. Gemini model-issued `thoughtSignature` parts accompany the exact native function call and must survive streamed/buffered tool results and journal replay; verify signed parts against visible text, tool names, IDs and arguments. Reject unsigned Gemini tool requests for every model ID, mismatched native history, or cross-model continuation rather than guessing model families or fabricating a signature. Older unsigned Gemini tool calls are therefore unavailable; text-only responses remain supported. Anthropic OAuth may target only its registered HTTPS inference endpoint, with refresh under the credential-store lock. Local fixture verification is not proof of live provider entitlement.
- Responses-family terminal failure events retain selected nested error message/code/type fields even when the response omits its status. An error or incomplete detail on a nominally completed envelope prevents tool execution and usage acceptance. Empty assistant text accompanying tool calls produces only call/result replay items; a standalone empty assistant remains invalid.
- Streaming framing and display-preview fast paths must be invariant to transport fragment width. Preserve CR/LF/CRLF boundaries, ordered multi-data SSE callbacks, exact line/event limits and incomplete EOF rejection without retaining unbounded spans. Printable-ASCII preview batching must preserve UTF-8 scalar eviction, split escapes/surrogates, path safety and truthful retained/omitted counts; singleton fragments must not pay bulk-copy overhead.
- Codex subscription inference is **not** public OpenAI Responses: use its account-scoped `/codex/responses` endpoint, bearer/JWT account and residency headers, mandatory streaming envelope and native encrypted reasoning replay. Persist opaque provider state only in the private journal; reject a different model, tampered visible text/tool calls or unsupported native output before replay, and omit provider state from foreign wire requests. OpenRouter alone does not echo authorization state: its browser grant uses a random PKCE verifier and a fixed loopback callback, then stores the exchanged key, not a renewable token. Do not disable state checks for standard OAuth providers. Personal GitHub Copilot uses a GitHub HTTPS device grant and pinned public Chat endpoint; let its account listing and the service decide available Chat model IDs rather than shipping a frozen allowlist, and do not claim Enterprise or non-Chat routes without implementing them.
- For Codex inference, obtain the selected model's Responses format from a fresh bounded, pinned HTTPS listing for the authenticated account before sending a request; do not infer it from the model name or reuse another account's metadata. Responses Lite moves instructions and function namespaces into developer input, sends the Lite header, requests all-turn reasoning context, and replays native namespaced tool calls. If the model or format is absent, report that limitation before posting rather than guessing standard Responses. Preserve existing model-bound opaque history and account-bound journal identity.
- Preserve fresh Codex account `supported_reasoning_levels` as bounded metadata: at most 16 unique, nonempty printable tokens of at most 32 bytes. Offer only tokens the selected native API can serialize; unknown future levels remain metadata, not fabricated controls. An explicit Codex effort reaches Standard and Lite `reasoning.effort`, overrides the Lite listing default, and is rechecked against the fresh authenticated account/model before inference when levels are reported. Missing metadata does not become a guessed list; an explicit empty list admits no override. No default remapping or automatic replay is allowed.
- Exclude Codex account-listing entries explicitly marked `supported_in_api: false` from selectable models, even when the account returned a slug. Do not invent a selectable alias for a `-wm` or other model suffix without an exact account-listed ID; an upstream catalog alias cannot prove this account's inference access.
- OpenAI Codex browser PKCE and device approval share the same account identity and pinned Responses route; preserve the stored grant kind across locked refresh. Device approval uses a fixed verification URL, bounded polling and the pinned authorization-code exchange, without a loopback callback or weakened provider/account/route binding.
- Authenticated model discovery is independent of wire routing. A model identity is the exact tuple `(provider, optional account ID, registered route, upstream ID)`; upstream IDs may contain slashes, and display labels are presentation-only. `--models` and background `/model`/setup/settings pickers may query only pinned provider listing endpoints or local Ollama tags; never forward a private API key or OAuth token to a caller-chosen host or follow listing redirects. Parse each account's complete bounded listing, including Anthropic cursor pages, before showing choices; refuse malformed pages, repeated cursors, duplicate IDs, missing pages or oversized pages rather than treating partial discovery as global truth. Fetch a fresh listing on every picker open; do not cache model rosters. Keep model-ID provenance separate from capability provenance; optional provider-reported capabilities retain their source and retrieval time, and absent values remain unknown. Listing membership alone never proves route, tool, context, or entitlement support. No selectable model IDs or implicit model defaults may be hardcoded. When discovery fails, show its error and accept an explicitly typed ID without claiming entitlement. Network lookup must not block input; cancel and reap its subprocess when the chooser exits.
- Mobile specialization starts with bounded inspection of actual project files, then identifies Swift/Xcode/SwiftPM, Android/Gradle, Flutter or React Native from manifests. `mobile_project` walks at most 10,000 workspace entries, retains at most 100 candidate manifests and 100 candidate shared scheme files, rejects regular manifests or schemes over 1 MiB, caps output at 65,536 bytes and marks truncated scans. It honors `.gitignore` and known generated/dependency exclusions and never follows symlinks. Suggested commands are inert evidence, never proof of SDK, scheme, simulator, signing permission or permission to execute.

- For Xcode inventory, report only bounded regular `.xcscheme` files under the exact verified bundle's `xcshareddata/xcschemes` directory, retaining the owning `.xcworkspace` or `.xcodeproj` path. Ignore `xcuserdata`; filenames never become executable scheme choices. `xcode_preflight` evaluates project code only after distinct explicit approvals for `schemes` (`xcodebuild -list -json`), `destinations` (`-showdestinations`) and one `build` or `test`. Scope discoveries to one private session, checked Xcode bundle, exact scheme, and an unchanged bounded project-input fingerprint covering the bundle manifest, its shared scheme files, and the manifests plus shared schemes of directly referenced `.xcodeproj` bundles (`group:`/`container:` workspace FileRefs and literal `path` entries in `project.pbxproj`). Missing, escaping, non-regular, oversized or unreadable in-scope inputs degrade the fingerprint: scheme discovery still runs but yields no verified choices, and any input change requires fresh approved discovery. Arbitrary executable project code is not fingerprintable. Accept only available iOS Simulator UUID destinations. Refuse missing/failed/truncated/malformed discovery, cross-bundle selection and headless approval. Preview the exact command and use `CODE_SIGNING_ALLOWED=NO`; preserve real exit/timeout/cancel status and never infer SDK readiness from fixtures.
- Real Xcode simulator discovery/build/test acceptance is manual-only on a separately available Mac with explicit per-command approval. Parse both Xcode's `Available/Ineligible destinations` and `Destinations compatible/incompatible with` headings; only UUIDs in the available/compatible iOS Simulator section can be selected. CI may run fake-executable safety regressions, but must not install xcodegen, select/boot a simulator or perform a real Xcode simulator build/test.
- Apple simulator inventory is a separate explicitly approved `xcode_preflight action=simulators` (`xcrun simctl list devices available -j`) after this session's approved scheme and destination discoveries for the same unchanged Xcode bundle. Intersect available iOS runtime devices with the scheme's verified simulator UUIDs; show only bounded, safe device names, runtime, UUID and Booted/Shutdown state, never local device paths, physical devices or other platforms. Missing tooling, failed/truncated/malformed output, changed manifests and absent matches yield no runnable choice. A successful inventory is retained per scheme in the session, and a `test` action additionally requires its destination UUID to be in that retained intersection; refreshing destinations, re-running or failing inventory, or a changed fingerprint drops it, while `build` remains destination-bound only. Inventory never boots or deploys a device.
- Android inventory is a separate shell-gated, private-session-only `android_devices` tool for one exact regular Gradle settings directory. Every invocation requires its own interactive approval, including in `yolo`; `action=avds` runs only `emulator -list-avds`, and `action=devices` runs only `adb devices` (which may start the local ADB server and use its configured identity). Reject missing, failed, timed-out, truncated, malformed or oversized output without offering a device. Report at most 100 safe configured AVD names as not running and image readiness unknown; show only bounded `emulator-NNNN[N]` serials as ready when ADB reports `device`. Label offline, unauthorized and other emulator transports unavailable; count physical/unclassified devices by state without revealing their serials. Inventory does not install an SDK, boot an AVD, pick a device, authorize a Gradle test or imply readiness from a configured AVD.
- Xcode simulator tests require an unchanged scheme's current approved destination and a successful approved simulator inventory on that exact scheme; refresh/failure clears the stored simulator choices. Android instrumentation binds the selected qualified task to the one serial from the current approved ready-emulator inventory using `ANDROID_SERIAL`. Every inventory/test command requires its own interactive approval; no physical serial may run an emulator test. Preserve `JAVA_HOME`, `ANDROID_HOME`, `ANDROID_SDK_ROOT` and `ANDROID_USER_HOME` for managed toolchain subprocesses, but continue excluding provider/custom credentials.
`mobile_session` is private-session-owned. A selection binds one checked workspace artifact, app identifier, exact approved Android emulator inventory or scheme-compatible iOS Simulator, selected variant/scheme, and optional package-scoped Android activity component. `list`, `status` and `/mobile` are read-only. Build, install, launch and stop each require a separate explicit approval showing the exact command, selected target, app and artifact. Build state changes only after successful non-truncated output and an existing artifact; device state changes only after successful non-truncated commands. Invalid transitions, denial and process failure preserve the prior state. Physical devices are never selectable. Tests remain separate approved platform actions; selection or inventory authorizes none of these effects.
- `mobile_verify` binds verification to one existing selected mobile app session, its project and exact device. It accepts only a pre-edit SHA-256 and post-edit SHA-256 evidenced by a guarded `apply_edits` chain in the current private session, checks the source is a regular workspace-contained file whose current hash equals the post-edit hash before execution and again afterward, and rejects caller-supplied pass metadata. The hashes may be equal when guarded edits introduce and then repair a defect back to the original bytes; evidence of that edit chain, not hash inequality, proves a change occurred. Build/test commands come only from the existing focused mobile command builders and receive normal exact-command, separate interactive approval. A pass requires real command success, complete output, and affirmative evidence that at least one test executed; stale source, mutation during execution, nonzero exit, timeout/cancellation, zero tests and truncation cannot be called verified. Source diagnostics are linkable only after checked workspace containment.
- `mobile_observe` is a read-only shell-gated observation of the exact running private-session app/device; each screenshot or tree capture requires its own explicit approval and bounded output. Return validated PNG bytes as an image block and parse Android UIAutomator XML without external entities, bounding bytes and node count. Treat all pixels/tree text as untrusted private app content. Use the available `simctl` path for iOS screenshots; when no approved system API exposes an iOS accessibility tree, report it unavailable rather than fabricating one or silently adding an automation dependency.
- `mobile_control` changes UI only for a running private Android app session and requires its own exact-command interactive approval. Tap/swipe coordinates must fit the most recent validated screenshot; invalidate that coordinate reference before executing an action. Bound swipe duration and text size, shell-quote remote text, encode spaces explicitly, and reject text that conflicts with Android's reserved encoding. Do not infer success beyond command exit status: callers separately capture fresh screenshot/accessibility state. Unsupported iOS simulator input is reported unavailable rather than simulated or silently delegated.
- `mobile_scenario` persists bounded, versioned Android scenarios only beneath an owner-checked private workspace store (0700 directory, 0600 atomic records), with exact project/app/device/build identity. Every replay start, single stored control step and accessibility verification/state transition requires its own approval; verification must capture a fresh device tree itself and compare an exact stored field/value, never trust caller-supplied trees or persist raw observations. Coordinate replay requires a fresh screenshot before each coordinate action. First failure persists and stops; no implicit retries, physical-device selection, iOS replay, or implied success from an input command.
- `mobile_diagnostics` is shell-gated, private-session-only and explicitly approved for every capture. Bind Android running-app logs to its current PID; bind crash history to the selected package and retain only actual CRASH/CRASH_NATIVE process-exit reasons; filter last-ANR records to that app. Use `simctl spawn ... log show` with a selected-process/bundle predicate for iOS Simulator logs and ReportCrash events, not a claim of `.ips` retrieval. Cap captured output at 1 MiB, mark truncated evidence incomplete and never promote foreign package records or normal process exits as crashes. Report the expected in-workspace Android mapping or iOS dSYM DWARF file only when it is a regular checked file; do not claim symbolication or turn untrusted frames into source links unless the captured evidence verifies the location.
`mobile_visual` saves or compares bounded PNG captures only for the exact running private app session. Baselines are private workspace records and bind app/platform/device, operator-declared OS/locale/theme, exact dimensions and exact dynamic-region masks; every screenshot command requires separate explicit approval. Reject incomplete captures and every metadata mismatch. Compare decoded pixels outside masks and report differences without treating time-dependent regions as implicitly ignored. On macOS, decode with the system Swift/ImageIO runtime; ImageIO performs the actual PNG decode and no project-provided image decoder is executed.
`/mobile` presents exact private app/device/lifecycle rows in newest-first numeric-ID order and preselects the newest existing session; the empty dashboard explains how to start. Listed sessions open their observation, control, scenario, diagnostics, guarded-verification and visual-baseline workflows. Chosen workflows enter the normal `Turn_runner`/Agent route as visible user prompts; they never call device tools directly or bypass approval. UI control requires explicit user intent, fresh observation and a settled-state observation. Back/Escape before submission preserves session/draft state; effects during a workflow still require normal per-call interactive approval and cancellation never grants consent.
- Before workspace writes, classify exact before/after bytes for mobile permission, entitlement, signing, bundle-ID and deployment/SDK configuration. Sensitive literal changes receive a distinct content-bound authorization through every mutation surface; unresolved executable configuration fails closed. Do not read signing keychains/keystores, reveal secrets, sign, or treat ordinary source changes as deployment approval.
- Flutter/RN consistency findings pair only supported literal bridge/config declarations with existing in-root native handlers, report both source locations and existing focused tests, and distinguish mismatch from unsupported/dynamic/absent evidence. Never execute a config or generate a bridge as part of the read-only inventory.

- For SwiftPM, read `Package.swift` only as bounded text. Report the package root and existing conventional `Tests/` directories as candidate test roots, not resolved target names; computed/unsupported target declarations and SDK requirements remain unknown.
- For Android Gradle, inspect only bounded `settings.gradle[.kts]` text for static literal `include` calls, with comments and string literals opaque. Report included module paths, regular wrapper scripts, and existing conventional `src/main`, `src/test` and `src/androidTest` directories as filesystem candidates. Never execute or infer settings logic, dynamic includes, `projectDir` remapping, tasks, build variants or SDK readiness.
- For Flutter, classify only bounded pubspec evidence: a literal `dependencies.flutter.sdk: flutter` identifies the framework, and a literal `flutter.plugin` marks plugins. Existing scanned `ios/` and `android/` directories are host-root evidence only, not proof of a buildable app or SDK availability. Dart-only and unreadable manifests supply no Flutter command.
- For React Native/Expo, use only bounded `package.json` string dependency and script entries. Lockfiles must be observed regular files beside that manifest; conflicting package managers or no lockfile require an explicit choice and suggest no script command. Report only existing scanned `ios/` and `android/` host directories. Never invoke `npx`, infer an absent script, install packages or claim that a native host builds.
- In mixed mobile workspaces, an inventory call lists bounded evidence but suggests no focused commands. `mobile_project` takes both an exact scanned `subroot` (the Xcode bundle for Xcode) and `ios`/`android` `platform` before showing inert commands for one uniquely matched stack. Mismatched, ambiguous, canceled, truncated or framework-owned nested native roots yield no command. Selection is per call; it does not change session, model or draft. Execution remains separately approved per command.
- `mobile_check` is shell-gated, private-session-only and individually approved for every invocation, including task discovery. Preview the exact command and working directory before execution; retain bounded output, actual exit, timeout and cancellation without turning missing tools or truncated discovery into success. SwiftPM test discovery/run binds an exact parsed test filter to one unchanged bounded regular `Package.swift` and refuses manifests with resolvable dependencies. Gradle task discovery/run binds an exact qualified task to one unchanged regular settings manifest and uses installed system `gradle --offline`; never implicitly download a wrapper distribution, plugin or dependency, and never replace a missing task/variant. Flutter analysis uses `--no-pub`; targeted tests require an existing package-owned `test/*.dart` and literal Flutter SDK pubspec evidence. React Native/Expo scripts require a declared string test/lint script, string framework dependency and an observed regular lockfile; conflicting managers need an explicit matching choice. Every project script/configuration is untrusted executable code, even when marked test or discovery. CI may provision toolchains and disposable projects separately from these commands; a fake executable never closes a platform runtime acceptance card. Gradle instrumented runs additionally require this session's approved `android_devices` inventory for the same settings root and an explicit `serial`; only an `emulator-NNNN[N]` serial reported `device` in that retained inventory may receive the task, delivered as `ANDROID_SERIAL` on the exact approved command. Offline, unauthorized, physical/unclassified or absent serials and stale or missing inventory fail before invocation; booting an emulator and standalone install remain separately approved actions, never implicit fallbacks.

- For failed approved Xcode build/test and SwiftPM focused runs, show up to 16 checked Swift `path:line:column: error` locations from bounded command output with the original exit and selected scheme or stack. Only existing regular `.swift` files resolving inside the chosen workspace become source-linked locations; external, malformed, symlinked or control-bearing lines remain raw untrusted output. A truncated log remains incomplete; a location is not proof that a test ran or authorization to edit.
- For failed approved Gradle, Flutter and RN/Expo focused checks, preserve the selected task/script, actual exit and raw bounded log. Source hints may name only existing regular files inside the selected project: the selected Gradle module's Kotlin/Java sources, the Flutter package's Dart sources, or the RN/Expo package's JS/TS sources. Reject generated/dependency, symlinked, external, malformed or control-bearing locations and cap deduplicated hints at 16. Do not infer success from diagnostic text, promote unrelated stack frames, or treat a partial/truncated log as complete.
- File tools resolve paths under the selected workspace, reject traversal and symlink escapes, bound reads/searches, and perform exact-match edits. Replacements must not silently target ambiguous spans. Atomic writes must keep the original on failure. A bounded tail selector may discard an oversized earlier line but must reject an oversized line still included in the selected tail; file scan and binary-content limits remain effective.
- Shell execution is disabled by default. `--allow-shell` advertises shell commands; prompt-required calls need explicit interactive approval and fail closed without an interactive surface. Only a matching `run_command` command-pattern allow rule can waive that prompt, never an ordinary per-tool allow or a managed-shell grant. Commands are **not** sandboxed. Device deployment, signing, destructive and credential operations require informed approval of that exact command.
- Opt-in sessions are private, append-only JSONL journals with stable parent-linked message IDs; branching retains prior messages, while forking creates a separate file containing the selected path. Existing flat JSON-array sessions migrate without dropping messages. Persist each assistant tool-call message before execution, fsync start before invoking a tool, and persist terminal settle/abort state before its provider result. Session-exit markers retain unresolved call IDs, names and known execution states without duplicating tool arguments. On restart, pair every unfinished call with exactly one conservative provider-valid tool result and never rerun calls whose side effects are unknown or may have occurred. Lifecycle and exit metadata remain branch-local and out of model context. A stale writer must fail rather than overwrite another session update. Session files can contain source and credentials surfaced by tools; do not commit them.
- Model selection is a parent-linked journal metadata entry separate from provider messages. Persist the canonical provider/account/route/upstream-ID identity; custom identities also carry an opaque configuration digest so edits to a route fail closed. Keep display labels separate, and never journal API keys, OAuth grants or custom endpoint values. On `/resume`, `--session` and `/branch`, resolve the selected ancestry's current identity against the registered route before changing TUI status; explicit CLI provider/model/API/endpoint overrides win. Preserve old journals without metadata, keep previews bounded past metadata to the first user prompt, and keep model markers out of replay, compaction and visible conversation.
- A successful top-level model response saves the exact provider/account/registered-route/upstream-ID identity as the last-used model for that canonical workspace in private user state, including initial CLI/configured models, resumed journals and headless use; custom routes retain their configuration digest. Explicit accepted interactive model selections also save immediately. Mere startup, session browsing, failed preflight/provider calls, cancelled pickers, discovery and background subagents never overwrite the preference. Compare on-disk identity under the existing lock before replacing unchanged state. On a fresh interactive launch without an explicit provider/model/API/endpoint/account, `--session`, or `--prompt`, a valid workspace last-used identity wins over configured launch defaults; an explicit selector or journal model wins over the recent choice, and headless launch precedence is unchanged. Reject stale or changed custom routes and malformed/insecure recent state rather than guessing an identity. This preference does not create a conversation journal or change the user/project defaults; model labels may be shortened visually, but selector matching, search, saved metadata and wire model IDs must remain exact.
- Persist thinking metadata, disabled tools, approval mode and entry labels as typed parent-linked journal entries, not provider messages; they follow the selected ancestry. Provider/model/API entries remain separate route metadata. Titles and pin changes are session-global journal metadata; the private recent-list pin index is only a projection. `/thinking` records branch-local metadata; adapters translate only documented provider controls, leave unsupported routes unchanged, and preserve opaque reasoning only for a matching provider/route/model. Fireworks reasoning effort and Alibaba's explicit boolean Qwen control do not imply that an arbitrary model supports thinking. Store user-image attachments as bounded top-level journal metadata, strip their bytes from the nested provider-message record, never send filenames, and reject unsupported routes before credential or network work; previews expose names/MIME labels only.
- User/project `settings.json` loads typed defaults with explicit CLI > project > user precedence and diagnostics for invalid files; a shell-disable policy in either file denies `--allow-shell` instead of silently granting it. Project settings writes use private, atomic replacements under a lock. User and ancestor `AGENTS.md` load below mobile safety, with bounded imports confined to their source directory. Path-scoped `.pave/rules` must resolve and enter the next model system context before a model-requested file edit/write is allowed; journal the first withheld call as unexecuted and fail closed on unsafe scopes. Project/system prompt sources are not higher-priority safety rules: optional user/project `SYSTEM.md`, `SYSTEM_TEMPLATE.md` (strict `{{root}}` interpolation only) and `APPEND_SYSTEM.md` have explicit CLI > project > user precedence, bounded UTF-8 regular-file reads and no promotion from tool results. A custom override cannot remove the mobile safety prompt or ancestor `AGENTS.md`.
- Tool approval modes are `always-ask` (prompt for writes and execution), `write` (allow reads/writes, prompt for execution) and `yolo` (allow all ordinary tool tiers); typed per-tool policies and command patterns refine the mode, with deny winning across user/project scopes. `run_command` still requires Pave's interactive per-command prompt under every mode and per-tool allow *unless a command pattern matches with `approval: allow`*; headless prompt-required calls fail closed. A `[w] always` grant persists an `exact` entry in user `tools.commandPatterns` matching the literal normalized command: retain quotes, escaped characters and significant argument whitespace; `*` inside it is data, never a wildcard. Approval previews identify the tool, tier, impact and arguments, and disclose unsandboxed shell execution. Allow rules match only one complete simple command; deny and prompt rules inspect compound subcommands so an allowed prefix cannot mask a denied later command.
- Tool and shell approvals use a dedicated transient viewport, not transcript rows or an editable-looking composer. Phrase the heading as a question about the action, lead with the exact primary argument (command, query, URL or path) emphasized, then the impact and remaining arguments; show the exact tool, tier and one-call scope in the subtitle. Place separate Deny / Allow once buttons, each naming its key, directly below the preview with denial initially selected; settings remain unchanged. Offer a third *Allow all TOOL* button only for `Approval.session_grantable` tools (web_search, web_fetch, write_file, edit_file, apply_edits, ast_edit, image_ocr, memory); its grant is in-memory, keyed by tool name and ends when the process exits. Shell, process, device, remote, publish and other external-effect tools never receive a session grant, so the button is absent for them.
- Offer permanent command consent only for a reviewed single-segment `run_command`, never `start_shell`, compound commands, a boolean-only confirmation or a secret-masked preview. Both TUI and line prompts must apply the same eligibility and refuse unusable persistence rather than promise a grant that cannot match.
- Consent fit includes the complete heading, scope, every action label, wrapped consequences and active timer, not just the argument preview. Stack buttons vertically when their full labels do not fit horizontally; any clipped consent text locks every non-safe action, including direct shortcuts. A cramped decision names its actual heading and safe action/key instead of generic denial, and advertises only that safe action plus resize until consent fits. Include the rendered gutter in the shortcut budget. Process-lifetime grants never turn an unsupported tool into a one-call allowance.
- Prepared tool execution and direct execution return explicit success content blocks or an error. Agent settlement, rewind eligibility and typed TUI events use that outcome; successful text beginning `Error:` is ordinary content, never an inferred failure. Journal replay resolves each card's outcome by call ID from the selected ancestry's lifecycle entries, including aborted calls. Denied write drafts say not written rather than failed. Only legacy untyped transcript text retains compatibility classification.
- The first-run wizard is gated to an interactive terminal with no explicit provider/model/session and no usable configured default. Persist only a versioned, user-scoped completion/skip marker and selected user model through owned, atomic config files; project policy and explicit CLI selection still win. Skipping an unset API key may save a model but must say prompts need the key; never solicit or render secret key text in TUI. OAuth sign-in uses the existing real handoff. `/setup` reopens the wizard; headless output remains untouched.
- Onboarding stage explanations belong to the chooser's transient presentation, not the transcript or persisted state. Give wide terminals concise step labels and keyboard guidance without reducing the searchable choice list below a usable page; narrow terminals omit explanatory rows. Resizing or typing a filter must not change the selected provider/model.
- Reuse the same cancellable, account-scoped model picker for setup, settings and `/model` rather than diverging discoverers. Picker titles, loading status and scope choices pair the provider's readable display name with the exact `provider@route[#account]` scope, and model rows name the provider; narrow composer headers keep the provider ID beside the model name when only the route/account must be dropped. `/model` opens a local provider list first (current provider, then ready providers, then providers needing credentials) and asks for an API/account only when the provider has several; it fetches only the one scope the user opens, and Esc or Tab in its model list returns to the provider list. `/model <filter>` searches the active provider/API/account directly, with Tab still reaching the provider list. Every opening fetches a new listing, including a return from scope browsing, without a roster cache or hidden-scope fan-out.
