# Pave design rules

The product goal is a maintainable OCaml mobile coding agent. The planned feature set is not yet complete. Implement and verify each vertical capability before exposing it; never advertise unfinished catalog, cancellation, LSP/DAP, subagent, extension or tool features as working.

- Provider identity, model routing, credential selection and wire serialization are separate contracts. A provider descriptor selects one supported API family and endpoint for a model; it must not send a foreign protocol through the Chat Completions adapter as a fallback. OpenAI Chat Completions and Anthropic Messages use distinct request/response wire adapters and a shared bounded SSE frame parser. A model turn produces either an assistant answer or tool calls; each call ID receives exactly one result before the next model turn. Invalid, truncated, failed, or refused responses must not execute partial calls. Bound tool turns, network requests, stream frames, shell runtime and tool output. Streaming can emit partial text before a terminal error; never persist that partial text as a completed assistant turn.
- OAuth authorization uses a cryptographically random PKCE verifier/state, exact redirect path and state validation, bounded loopback callbacks and explicit user sign-in. Store access/refresh tokens in a private, bounded, atomically replaced credential file; never put them in a journal, command line or diagnostic. Refresh before expiry while locking read-refresh-write against other processes. A login is not working provider inference until its distinct wire transport sends a real authenticated request and handles tool results correctly.
- OpenAI Responses, native Ollama and direct Gemini have their own request/response and streaming adapters. SSE and Ollama NDJSON parsing are bounded independently. Gemini 3 model-issued `thoughtSignature` parts accompany the exact native function call and must survive streamed/buffered tool results and journal replay; verify signed parts against visible text, tool names, IDs and arguments. Reject unsigned Gemini 3 tool requests, mismatched native history, or cross-model continuation rather than fabricating a signature. Anthropic OAuth may target only its registered HTTPS inference endpoint, with refresh under the credential-store lock. Local fixture verification is not proof of live provider entitlement.
- Codex subscription inference is **not** public OpenAI Responses: use its account-scoped `/codex/responses` endpoint, bearer/JWT account and residency headers, mandatory streaming envelope and native encrypted reasoning replay. Persist opaque provider state only in the private journal; reject a different model, tampered visible text/tool calls or unsupported native output before replay, and omit provider state from foreign wire requests. OpenRouter alone does not echo authorization state: its browser grant uses a random PKCE verifier and a fixed loopback callback, then stores the exchanged key, not a renewable token. Do not disable state checks for standard OAuth providers. Personal GitHub Copilot uses a GitHub HTTPS device grant, pinned public Chat endpoint and explicit supported models; never send its OAuth bearer to a configured host or an unsupported model, and do not claim Enterprise or non-Chat routes without implementing them.
- Authenticated model discovery is independent of model routing. `--models` may query only a provider's fixed listing endpoint (OpenAI, Gemini, personal Copilot) or local Ollama tags; never forward a private gateway API key or OAuth token to a caller-chosen host, follow listing redirects, or treat a listed model as an implemented transport. Pin curated offline suggestions separately from per-account live listings.
- Mobile specialization starts with repository inspection, then identifies Swift/Xcode/SwiftPM, Android/Gradle, Flutter or React Native from actual manifests. Never assume SDKs, simulators, signing keys or deployment permission. Follow local conventions and prefer focused builds/tests.
- File tools resolve paths under the selected workspace, reject traversal and symlink escapes, bound reads/searches, and perform exact-match edits. Replacements must not silently target ambiguous spans. Atomic writes must keep the original on failure.
- Shell execution is disabled by default. `--allow-shell` advertises shell commands but still requires explicit interactive approval for **each** command; noninteractive sessions deny execution. Commands are **not** sandboxed. Device deployment, signing, destructive and credential operations require informed approval of that exact command.
- API keys come from environment variables, not checked-in configuration or subprocess arguments. Opt-in sessions are private, append-only JSONL journals with stable parent-linked message IDs; branching retains prior messages, while forking creates a separate file containing the selected path. Existing flat JSON-array sessions migrate without dropping messages. Each message is durable before the agent advances; on restart unresolved tool calls receive recorded failure results and are never automatically re-executed. A stale writer must fail rather than overwrite another session update. Session files can contain source and credentials surfaced by tools; do not commit them.
- User/project `settings.json` loads typed defaults with explicit CLI > project > user precedence and diagnostics for invalid files; a shell-disable policy in either file denies `--allow-shell` instead of silently granting it. Project settings writes use private, atomic replacements under a lock. User and project `AGENTS.md` files are bounded, symlink-safe and appended after mobile safety text; imports remain inside their source directory. Path-scoped rules are not enforced on tool calls until per-path integration is complete.
- Manual compaction appends a summary and first-kept user entry ID to the same journal; it never rewrites historical entries. Rebuilt model context uses the latest compaction on the selected ancestry path, then the kept turn and later messages. Do not compact unresolved tool calls; provider failure leaves the original model context and journal unchanged. Distinguish a summary of prior work from actual tool results.
- The TUI edits Unicode grapheme clusters, renders by terminal cell width, preserves UTF-8 codepoints across terminal reads and replaces malformed input. Keep keyboard/status/error feedback visible, limit in-memory transcript to the most recent 10,000 rows and draft bytes, coalesce queued keypress repaints, redraw only changed rows, and block without idle polling. Model turns run on a cancellable worker that queues UI events and wakes the terminal by pipe; only the UI thread paints or confirms shell commands. Keep submitted follow-ups out of the transcript until their turn starts, retract provisional text on cancellation/error, and settle every journaled tool call even if a command is interrupted. Support resize and multiline paste; preserve non-TTY output and reject shell approvals when the command cannot fit in the visible confirmation.
- Render the Pave mark as static ASCII only in the empty interactive transcript viewport; derive its pixel silhouette from `assets/pave-mark.svg`, center it without touching the journal, and use a compact label when the viewport is too small. Any transcript content replaces the illustration; non-TTY output remains unchanged.
- Interactive slash commands parse before model input: unknown slash forms must not reach a provider. `/login` reuses the CLI credential-store flow, releases the terminal from raw/alternate-screen mode while printing a browser URL or GitHub device verification code and awaiting authorization, then restores the same transcript/editor even on errors. Provider/model selection is explicit, recomputes the registered wire route, clears stale endpoint overrides and rebuilds the agent from journal or in-memory history. Do not require credentials before entering the interactive UI, but resolve them before appending a new prompt. Strip opaque Codex or Gemini continuation when the new model or protocol differs, while retaining visible messages.
- Release archives must contain the native executable plus MIT and linked-library notices. The installer must verify the published SHA-256 checksum and archive contents before atomically replacing a binary; unsupported platforms and missing releases fail closed. Published documents and history must not retain legacy branding; legally required copyright and permission notices remain.
- Native self-update belongs only to a binary installed by the release installer, never an opam/foreign package. Embed that installer from the checked-in `install.sh` at build time; do not download and execute a fresh shell script. Find the running binary's install directory, require the native-install marker, ignore inherited update destination/version overrides, and retain HTTPS-only fetch, four-entry SHA-256 manifest, exact regular archive members and staged atomic binary rename. The marker is an install-layout hint, not an authentication signature.
- Release builds embed their validated tag into the binary from the release workflow, while source builds report no release version. `pave update --check` compares that tag against bounded HTTPS release metadata without changing installed files; errors must not become false “up-to-date” reports. Model defaults and wire routes must follow current official model documentation, not a stale compatible Chat fallback.
- CLI and tests must exercise real HTTP completion/tool-call behavior, not just schema wiring. Keep domain modules small and keep provider-specific wire handling outside the tool loop.
