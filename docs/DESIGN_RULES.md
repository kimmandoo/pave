# Pave design rules

The product goal is a maintainable OCaml mobile coding agent. The planned feature set is not yet complete. Implement and verify each vertical capability before exposing it; never advertise unfinished catalog, LSP/DAP, subagent, extension or tool features as working.

- Provider identity, model routing, credential selection and wire serialization are separate contracts. A provider descriptor selects one supported API family and endpoint for a model; it must not send a foreign protocol through the Chat Completions adapter as a fallback. OpenAI Chat Completions and Anthropic Messages use distinct request/response wire adapters and a shared bounded SSE frame parser. A model turn produces either an assistant answer or tool calls; each call ID receives exactly one result before the next model turn. Invalid, truncated, failed, or refused responses must not execute partial calls. A Chat Completions `[DONE]` sentinel without a preceding valid `finish_reason` is truncated, not successful; a `stop` finish reason with tool calls must also fail before any tool executes. Bound tool turns, network requests, stream frames, shell runtime and tool output. Streaming can emit partial text before a terminal error; never persist that partial text as a completed assistant turn.
- OAuth authorization uses a cryptographically random PKCE verifier/state, exact redirect path and state validation, bounded loopback callbacks and explicit user sign-in. Store access/refresh tokens in a private, bounded, atomically replaced credential file; never put them in a journal, command line or diagnostic. Refresh before expiry while locking read-refresh-write against other processes. A login is not working provider inference until its distinct wire transport sends a real authenticated request and handles tool results correctly.
- The OAuth store separates the provider-reported account ID from the account selector. Preserve provider IDs unchanged for wire headers; when no provider ID exists, assign a cryptographically random `pave-local:<hex>` selector scoped to the local store. Sort selectors deterministically, require explicit selection when multiple grants exist, and permit multiple accountless grants without inventing provider identity. Migrate older store versions under the same lock and retain provider/grant/registered-route binding.
- Resolve an exact account-scoped selector or saved journal/workspace model identity before looking up a launch credential; infer the account only when one saved grant exists. When multiple grants remain for an unscoped model, an interactive prompt must select a grant before submission and persist that account with the model identity; cancelling restores the draft. Headless prompts must fail closed and require an account selector rather than choose a grant by ordering or model name.
- Resolve provider, grant, account selector, credential kind (API key, bound OAuth grant or cloud identity) and registered endpoint before any authenticated HTTP request; reject mismatches without sending credentials. Keep Vertex ADC and Bedrock AWS credentials separate from API-key and OAuth tokens. An environment API key visibly takes precedence over a saved grant; never offer a key text editor without a separately designed private lifecycle.
- `--mask-secrets` is opt-in local exact-value redaction for the active provider API key and OAuth access token. Use collision-safe reversible placeholders for tool arguments before execution, and one-way redaction for UI/event output; do not claim to cover images, opaque state, ambient identities, transformed or unknown values, or previously persisted journal content. It is not encryption and does not control provider retention.
- Keep OAuth tokens in the private local store unless a real deployable remote broker and explicit trust model exist; do not substitute an imaginary hosted service.
- Apple Foundation Models is an on-device, text-only route available only when the macOS arm64 helper is packaged or installed. Expose only the OS-managed `default` selector, not a fabricated remote model roster; verify runtime availability before generation, never invent a credential, and do not expose Pave workspace tools or claim file, shell, or network access. Reject unsupported media and show the specific macOS/Apple Intelligence readiness requirement.
- OpenAI Responses, native Ollama and direct Gemini have their own request/response and streaming adapters. SSE and Ollama NDJSON parsing are bounded independently. Gemini model-issued `thoughtSignature` parts accompany the exact native function call and must survive streamed/buffered tool results and journal replay; verify signed parts against visible text, tool names, IDs and arguments. Reject unsigned Gemini tool requests for every model ID, mismatched native history, or cross-model continuation rather than guessing model families or fabricating a signature. Older unsigned Gemini tool calls are therefore unavailable; text-only responses remain supported. Anthropic OAuth may target only its registered HTTPS inference endpoint, with refresh under the credential-store lock. Local fixture verification is not proof of live provider entitlement.
- Codex subscription inference is **not** public OpenAI Responses: use its account-scoped `/codex/responses` endpoint, bearer/JWT account and residency headers, mandatory streaming envelope and native encrypted reasoning replay. Persist opaque provider state only in the private journal; reject a different model, tampered visible text/tool calls or unsupported native output before replay, and omit provider state from foreign wire requests. OpenRouter alone does not echo authorization state: its browser grant uses a random PKCE verifier and a fixed loopback callback, then stores the exchanged key, not a renewable token. Do not disable state checks for standard OAuth providers. Personal GitHub Copilot uses a GitHub HTTPS device grant and pinned public Chat endpoint; let its account listing and the service decide available Chat model IDs rather than shipping a frozen allowlist, and do not claim Enterprise or non-Chat routes without implementing them.
- For Codex inference, obtain the selected model's Responses format from a fresh bounded, pinned HTTPS listing for the authenticated account before sending a request; do not infer it from the model name or reuse another account's metadata. Responses Lite moves instructions and function namespaces into developer input, sends the Lite header, requests all-turn reasoning context, and replays native namespaced tool calls. If the model or format is absent, report that limitation before posting rather than guessing standard Responses. Preserve existing model-bound opaque history and account-bound journal identity.
- Exclude Codex account-listing entries explicitly marked `supported_in_api: false` from selectable models, even when the account returned a slug. Do not invent a selectable alias for a `-wm` or other model suffix without an exact account-listed ID; an upstream catalog alias cannot prove this account's inference access.
- OpenAI Codex browser PKCE and device approval share the same account identity and pinned Responses route; preserve the stored grant kind across locked refresh. Device approval uses a fixed verification URL, bounded polling and the pinned authorization-code exchange, without a loopback callback or weakened provider/account/route binding.
- Authenticated model discovery is independent of wire routing. A model identity is the exact tuple `(provider, optional account ID, registered route, upstream ID)`; upstream IDs may contain slashes, and display labels are presentation-only. `--models` and background `/model`/setup/settings pickers may query only pinned provider listing endpoints or local Ollama tags; never forward a private API key or OAuth token to a caller-chosen host or follow listing redirects. Parse each account's complete bounded listing, including Anthropic cursor pages, before showing choices; refuse malformed pages, repeated cursors, duplicate IDs, missing pages or oversized pages rather than treating partial discovery as global truth. Fetch a fresh listing on every picker open; do not cache model rosters. Keep model-ID provenance separate from capability provenance; optional provider-reported capabilities retain their source and retrieval time, and absent values remain unknown. Listing membership alone never proves route, tool, context, or entitlement support. No selectable model IDs or implicit model defaults may be hardcoded. When discovery fails, show its error and accept an explicitly typed ID without claiming entitlement. Network lookup must not block input; cancel and reap its subprocess when the chooser exits.
- Mobile specialization starts with bounded inspection of actual project files, then identifies Swift/Xcode/SwiftPM, Android/Gradle, Flutter or React Native from manifests. `mobile_project` walks at most 10,000 workspace entries, retains at most 100 candidate manifests and 100 candidate shared scheme files, rejects regular manifests or schemes over 1 MiB, caps output at 65,536 bytes and marks truncated scans. It honors `.gitignore` and known generated/dependency exclusions and never follows symlinks. Suggested commands are inert evidence, never proof of SDK, scheme, simulator, signing permission or permission to execute.

- For Xcode inventory, report only bounded regular `.xcscheme` files under the exact verified bundle's `xcshareddata/xcschemes` directory, retaining the owning `.xcworkspace` or `.xcodeproj` path. Ignore `xcuserdata`; filenames never become executable scheme choices. `xcode_preflight` evaluates project code only after distinct explicit approvals for `schemes` (`xcodebuild -list -json`), `destinations` (`-showdestinations`) and one `build` or `test`. Scope discoveries to one private session, checked Xcode bundle, unchanged manifest hash and exact scheme; accept only available iOS Simulator UUID destinations. Refuse missing/failed/truncated/malformed discovery, cross-bundle selection and headless approval. Preview the exact command and use `CODE_SIGNING_ALLOWED=NO`; preserve real exit/timeout/cancel status and never infer SDK readiness from fixtures.
- Real Xcode simulator discovery/build/test acceptance is manual-only on a separately available Mac with explicit per-command approval. Parse both Xcode's `Available/Ineligible destinations` and `Destinations compatible/incompatible with` headings; only UUIDs in the available/compatible iOS Simulator section can be selected. CI may run fake-executable safety regressions, but must not install xcodegen, select/boot a simulator or perform a real Xcode simulator build/test.
- Apple simulator inventory is a separate explicitly approved `xcode_preflight action=simulators` (`xcrun simctl list devices available -j`) after this session's approved scheme and destination discoveries for the same unchanged Xcode bundle. Intersect available iOS runtime devices with the scheme's verified simulator UUIDs; show only bounded, safe device names, runtime, UUID and Booted/Shutdown state, never local device paths, physical devices or other platforms. Missing tooling, failed/truncated/malformed output, changed manifests and absent matches yield no runnable choice. Inventory never boots or deploys a device and does not authorize a later test.
- Android inventory is a separate shell-gated, private-session-only `android_devices` tool for one exact regular Gradle settings directory. Every invocation requires its own interactive approval, including in `yolo`; `action=avds` runs only `emulator -list-avds`, and `action=devices` runs only `adb devices` (which may start the local ADB server and use its configured identity). Reject missing, failed, timed-out, truncated, malformed or oversized output without offering a device. Report at most 100 safe configured AVD names as not running and image readiness unknown; show only bounded `emulator-NNNN[N]` serials as ready when ADB reports `device`. Label offline, unauthorized and other emulator transports unavailable; count physical/unclassified devices by state without revealing their serials. Inventory does not install an SDK, boot an AVD, pick a device, authorize a Gradle test or imply readiness from a configured AVD.
- For SwiftPM, read `Package.swift` only as bounded text. Report the package root and existing conventional `Tests/` directories as candidate test roots, not resolved target names; computed/unsupported target declarations and SDK requirements remain unknown.
- For Android Gradle, inspect only bounded `settings.gradle[.kts]` text for static literal `include` calls, with comments and string literals opaque. Report included module paths, regular wrapper scripts, and existing conventional `src/main`, `src/test` and `src/androidTest` directories as filesystem candidates. Never execute or infer settings logic, dynamic includes, `projectDir` remapping, tasks, build variants or SDK readiness.
- For Flutter, classify only bounded pubspec evidence: a literal `dependencies.flutter.sdk: flutter` identifies the framework, and a literal `flutter.plugin` marks plugins. Existing scanned `ios/` and `android/` directories are host-root evidence only, not proof of a buildable app or SDK availability. Dart-only and unreadable manifests supply no Flutter command.
- For React Native/Expo, use only bounded `package.json` string dependency and script entries. Lockfiles must be observed regular files beside that manifest; conflicting package managers or no lockfile require an explicit choice and suggest no script command. Report only existing scanned `ios/` and `android/` host directories. Never invoke `npx`, infer an absent script, install packages or claim that a native host builds.
- In mixed mobile workspaces, an inventory call lists bounded evidence but suggests no focused commands. `mobile_project` takes both an exact scanned `subroot` (the Xcode bundle for Xcode) and `ios`/`android` `platform` before showing inert commands for one uniquely matched stack. Mismatched, ambiguous, canceled, truncated or framework-owned nested native roots yield no command. Selection is per call; it does not change session, model or draft. Execution remains separately approved per command.
- `mobile_check` is shell-gated, private-session-only and individually approved for every invocation, including task discovery. Preview the exact command and working directory before execution; retain bounded output, actual exit, timeout and cancellation without turning missing tools or truncated discovery into success. SwiftPM test discovery/run binds an exact parsed test filter to one unchanged bounded regular `Package.swift` and refuses manifests with resolvable dependencies. Gradle task discovery/run binds an exact qualified task to one unchanged regular settings manifest and uses installed system `gradle --offline`; never implicitly download a wrapper distribution, plugin or dependency, and never replace a missing task/variant. Flutter analysis uses `--no-pub`; targeted tests require an existing package-owned `test/*.dart` and literal Flutter SDK pubspec evidence. React Native/Expo scripts require a declared string test/lint script, string framework dependency and an observed regular lockfile; conflicting managers need an explicit matching choice. Every project script/configuration is untrusted executable code, even when marked test or discovery. CI may provision toolchains and disposable projects separately from these commands; a fake executable never closes a platform runtime acceptance card.

- For failed approved Xcode build/test and SwiftPM focused runs, show up to 16 checked Swift `path:line:column: error` locations from bounded command output with the original exit and selected scheme or stack. Only existing regular `.swift` files resolving inside the chosen workspace become source-linked locations; external, malformed, symlinked or control-bearing lines remain raw untrusted output. A truncated log remains incomplete; a location is not proof that a test ran or authorization to edit.
- For failed approved Gradle, Flutter and RN/Expo focused checks, preserve the selected task/script, actual exit and raw bounded log. Source hints may name only existing regular files inside the selected project: the selected Gradle module's Kotlin/Java sources, the Flutter package's Dart sources, or the RN/Expo package's JS/TS sources. Reject generated/dependency, symlinked, external, malformed or control-bearing locations and cap deduplicated hints at 16. Do not infer success from diagnostic text, promote unrelated stack frames, or treat a partial/truncated log as complete.
- File tools resolve paths under the selected workspace, reject traversal and symlink escapes, bound reads/searches, and perform exact-match edits. Replacements must not silently target ambiguous spans. Atomic writes must keep the original on failure. A bounded tail selector may discard an oversized earlier line but must reject an oversized line still included in the selected tail; file scan and binary-content limits remain effective.
- Shell execution is disabled by default. `--allow-shell` advertises shell commands but still requires explicit interactive approval for **each** command; noninteractive sessions deny execution. Commands are **not** sandboxed. Device deployment, signing, destructive and credential operations require informed approval of that exact command.
- Opt-in sessions are private, append-only JSONL journals with stable parent-linked message IDs; branching retains prior messages, while forking creates a separate file containing the selected path. Existing flat JSON-array sessions migrate without dropping messages. Persist each assistant tool-call message before execution, fsync start before invoking a tool, and persist terminal settle/abort state before its provider result. Session-exit markers retain unresolved call IDs, names and known execution states without duplicating tool arguments. On restart, pair every unfinished call with exactly one conservative provider-valid tool result and never rerun calls whose side effects are unknown or may have occurred. Lifecycle and exit metadata remain branch-local and out of model context. A stale writer must fail rather than overwrite another session update. Session files can contain source and credentials surfaced by tools; do not commit them.
- Model selection is a parent-linked journal metadata entry separate from provider messages. Persist the canonical provider/account/route/upstream-ID identity; custom identities also carry an opaque configuration digest so edits to a route fail closed. Keep display labels separate, and never journal API keys, OAuth grants or custom endpoint values. On `/resume`, `--session` and `/branch`, resolve the selected ancestry's current identity against the registered route before changing TUI status; explicit CLI provider/model/API/endpoint overrides win. Preserve old journals without metadata, keep previews bounded past metadata to the first user prompt, and keep model markers out of replay, compaction and visible conversation.
- A successful interactive model switch also saves the exact provider/account/registered-route/upstream-ID identity as the last-used model for that canonical workspace in private user state; custom routes retain their configuration digest. On a fresh interactive launch without an explicit provider/model/API/endpoint/account, `--session`, or `--prompt`, a valid workspace last-used identity wins over configured launch defaults; an explicit selector or journal model wins over the recent choice. Reject stale or changed custom routes and malformed/insecure recent state rather than guessing an identity. This preference does not create a conversation journal or change the user/project defaults; model labels may be shortened visually, but selector matching, search, saved metadata and wire model IDs must remain exact.
- Persist thinking metadata, disabled tools, approval mode and entry labels as typed parent-linked journal entries, not provider messages; they follow the selected ancestry. Provider/model/API entries remain separate route metadata. Titles and pin changes are session-global journal metadata; the private recent-list pin index is only a projection. `/thinking` records branch-local metadata; adapters translate only documented provider controls, leave unsupported routes unchanged, and preserve opaque reasoning only for a matching provider/route/model. Fireworks reasoning effort and Alibaba's explicit boolean Qwen control do not imply that an arbitrary model supports thinking. Store user-image attachments as bounded top-level journal metadata, strip their bytes from the nested provider-message record, never send filenames, and reject unsupported routes before credential or network work; previews expose names/MIME labels only.
- User/project `settings.json` loads typed defaults with explicit CLI > project > user precedence and diagnostics for invalid files; a shell-disable policy in either file denies `--allow-shell` instead of silently granting it. Project settings writes use private, atomic replacements under a lock. User and ancestor `AGENTS.md` load below mobile safety, with bounded imports confined to their source directory. Path-scoped `.pave/rules` must resolve and enter the next model system context before a model-requested file edit/write is allowed; journal the first withheld call as unexecuted and fail closed on unsafe scopes. Project/system prompt sources are not higher-priority safety rules: optional user/project `SYSTEM.md`, `SYSTEM_TEMPLATE.md` (strict `{{root}}` interpolation only) and `APPEND_SYSTEM.md` have explicit CLI > project > user precedence, bounded UTF-8 regular-file reads and no promotion from tool results. A custom override cannot remove the mobile safety prompt or ancestor `AGENTS.md`.
- Tool approval modes are `always-ask` (prompt for writes and execution), `write` (allow reads/writes, prompt for execution) and `yolo` (allow all ordinary tool tiers); typed per-tool policies and command patterns refine the mode, with deny winning across user/project scopes. `run_command` still requires Pave's interactive per-command prompt under every mode and per-tool allow; headless prompt-required calls fail closed. Approval previews identify the tool, tier, impact and arguments, and explicitly disclose that shell commands run unsandboxed. Command-pattern allow rules match only one simple command; deny and prompt rules inspect compound subcommands so an allowed prefix cannot mask a denied later command.
- A visible approval preview must fit above the composer, active row and shortcut overlay before `y` can authorize an effect. If resizing clips a pending preview, show a short resize hint, retain the pending choice and deny `y` until the full preview fits again; other keys may deny immediately. Never treat a clipped preview as informed consent.
- The first-run wizard is gated to an interactive terminal with no explicit provider/model/session and no usable configured default. Persist only a versioned, user-scoped completion/skip marker and selected user model through owned, atomic config files; project policy and explicit CLI selection still win. Skipping an unset API key may save a model but must say prompts need the key; never solicit or render secret key text in TUI. OAuth sign-in uses the existing real handoff. `/setup` reopens the wizard; headless output remains untouched.
- Onboarding stage explanations belong to the chooser's transient presentation, not the transcript or persisted state. Give wide terminals concise step labels and keyboard guidance without reducing the searchable choice list below a usable page; narrow terminals omit explanatory rows. Resizing or typing a filter must not change the selected provider/model.
- Reuse the same cancellable, account-scoped model picker for setup, settings and `/model` rather than diverging discoverers. A bounded coordinator snapshots each provider/account/route independently as loading, ready, unsupported or failed; partial success remains usable, and unavailable states appear in status rather than as selectable models. Fetch fresh listings on every open with no roster cache. Discovery must call pinned provider listing endpoints only, never an override URL with an OAuth token; preserve supported wire-route validation before selection and put wizard navigation controls after live candidates without labeling controls as model IDs. Newly available models may become the first choice only while the user has not navigated or filtered; preserve an explicit user selection on subsequent updates. Each open picker exclusively owns keyboard input, including Ctrl+C; cancellation closes only that picker, leaves the composer and selected model/default unchanged, and stops any cancellable discovery worker. Account handoff owns terminal input until return; discard pending type-ahead before restoring TUI focus.
- `/model` and the shared setup/settings model picker show only fresh, selectable model IDs for the chosen credential/account and registered API route; do not mingle static suggestions, arbitrary typed IDs, unclassified route claims, public catalogs without required inference credentials, unverified OS-managed defaults, unavailable provider routes, or route-browse commands with model candidates. An empty or failed listing stays empty and explains why; setup navigation remains a separate control. Preserve explicit CLI/session selectors for users who already know an unlisted model ID. A successful listing and local credential do not prove remote inference entitlement: do not label a model as permission-verified without a provider guarantee. Limit discovery workers, bound each request and avoid redundant unauthenticated traffic; maintain cancellation and account identity.
- Devin Connect routers without `modelFeatures` support tools unless an explicit `supportsToolCalls: false` denies them; exclude explicit tool-disabled models from the interactive model picker because the agent sends tools. Normalize nullable tool schemas for either a Gemini-selected model or its Gemini-assigned backend, preserving ordinary JSON Schema for other backends. Its pinned binary transport reads a complete three-byte HTTP status across fragmented pipe reads, reports allowlisted curl exit causes and HTTP/Connect error codes without showing response bodies, headers or credentials, and never automatically replays a timed-out completion.
- Set `--context-window TOKENS` only for the exact initial provider/model/API/endpoint. `auto` may consume only a fresh pinned listing's raw positive limit for the exact model: Command Code `context_length` plus its advertised API route, Google `inputTokenLimit`, account-scoped Codex `context_window`, Devin Connect `maxTokens`, OpenRouter account `/models/user` `context_length` through its single registered Chat route, or Anthropic `max_input_tokens` on its sole direct Messages route. Preserve OpenRouter `top_provider.max_completion_tokens` only as provider-reported output metadata; it does not replace the context window, but caps the byte-proxy output reserve when lower than its default. Anthropic native compaction additionally requires explicit true `capabilities.compaction.supported` and `capabilities.compaction.summarize.supported`, official `api.anthropic.com/v1/messages`, and API-key auth; replay the exact signed block only on that route/model and include the beta header. Listings without per-model route claims are accepted only for these providers' single registered route; a nonregistered endpoint override fails closed. Never infer limits from model names or apply family fallbacks. Devin `tokenizerType` is display-only metadata; local budgeting remains a conservative UTF-8 byte proxy, not provider tokenization. `/context` names the source and distinguishes window/output reserve from the proxy; count media payload bytes in the proxy while leaving media token costs unknown. Before each request, trim oversized text tool results only in provider-facing copies, then summarize older complete turns in bounded chunks if needed. Preserve the latest user turn and attachments, tool-call/result adjacency, signed provider replay where valid, and immutable journal history. Persist a branch-local compaction marker only after all summaries succeed; generic summarization must fail closed rather than discard signed state valid for the active route. Direct OpenAI Responses and capability-advertised Anthropic Messages are the only native compaction routes.
- The TUI edits Unicode grapheme clusters, renders by terminal cell width, preserves UTF-8 codepoints across terminal reads and replaces malformed input. Keep keyboard/status/error feedback visible, limit in-memory transcript to the most recent 10,000 rows and draft bytes, coalesce queued keypress repaints, redraw only changed rows, and block without idle polling. While a turn is active, render a high-contrast activity row immediately above the editor/footer with a spinner, typed model/tool phase and elapsed time; keep its timer tied to the turn rather than resetting it on phase changes, including in pickers and shell approval, and remove it when idle. Never display private model chain-of-thought as activity. Model turns run on a cancellable worker that queues UI events and wakes the terminal by pipe; only the UI thread paints or confirms shell commands. Each notice carries its turn ID and is accepted only from that turn's worker thread; ignore stale notices/completions after handoff. Serialize cancellation against completion: a cancellation that wins before a normal completion is enqueued must produce `Cancelled`, and deliver one terminal outcome so the UI can settle its owner. Once cancellation is requested, discard queued message/delta/phase notices for that turn while still delivering its terminal completion. Send typed model/tool phase notices through the same worker queue rather than guessing progress from transcript strings; mark a tool active only when execution begins, label the model phase `Responding` once the turn delivers visible text (without resetting the turn timer), return to model status for a follow-up request and clear activity on completion/cancel/error. Keep submitted follow-ups out of the transcript until their turn starts, retract provisional text on cancellation/error, and settle every journaled tool call even if a command is interrupted. Support resize and multiline paste; preserve non-TTY output and reject shell approvals when the command cannot fit in the visible confirmation.
- The activity spinner advances every 80 ms (about 12.5 frames/s) while its elapsed-time text stays in whole seconds; between frames only the activity row may change, and it is repainted in place over the full width without clearing it first, including in a three-row terminal, so an unchanged frame does not flicker or leave stale cells. Clip long phase names at grapheme boundaries to keep elapsed time visible in narrow windows; omit byte counts when space runs out. In terminals shorter than six rows, use spare rows for the most recent transcript lines (or chooser title), not blank padding; after a three-row turn completes the answer must replace the activity row without resizing. A bracketed paste replaces selected draft bytes within the 16,384-byte composer limit; retain the longest complete-codepoint prefix that fits, report truncation, and never submit pasted newlines or commands.
- Style normal active progress with the accent rather than the warning color. Show busy-only cancellation, steering and queue shortcuts; restore idle navigation hints when the turn finishes. In compact viewports, report the range of transcript rows actually displayed and shorten overlong footer text with an ellipsis instead of cutting a word in half.
- Use a single-cell dot-pattern activity indicator rather than half-disc glyphs; preserve the 80 ms spinner cadence, whole-second elapsed text, high contrast, phase and elapsed-time budget in `NO_COLOR` and narrow terminals. In compact model headers spell out `SAVED`/`UNSAVED` rather than showing ambiguous initials. When the transcript is empty, the idle compact footer should offer a usable prompt/help hint instead of scrolling or tool-detail actions. Terminal-signal exceptions must escape command-level error reporting, including while a chooser or unsaved-conversation confirmation is active, so terminal modes are restored on exit.
- Route terminal input, resize, runner/listing/approval/background results and shutdown through one typed TUI queue drained on the UI thread. Publish under the queue lock and wake on empty-to-nonempty transitions; never lose a wake or duplicate a submission. Normalize physical CR/LF as Return, disable terminal ICRNL/INLCR/IGNCR while raw so pasted CRLF remains one draft newline, and never execute bracket-pasted commands or approvals. Restore terminal modes and prior signal handlers before exiting on INT, HUP, QUIT, TERM or TSTP; `Tui.suspend` must release the terminal for external authentication, then rebuild raw mode and repaint after normal return or callback exception, discard callback type-ahead, preserve editor draft/transcript scroll/focus, and honor resize.
- The turn runner exposes owner-tagged `Turn_started`, `Transcript_message`, `Text_delta`, `Activity_phase`, `Tool_event`, `Turn_completed`, `Turn_cancelled` and `Turn_failed` events through one typed callback. A `Tool_event` carries the provider call ID and a start/update/settle/abort outcome; start/update notices obey the owning worker-thread and cancellation gates, while settle/abort results remain deliverable after cancellation. `Turn_started` is emitted on the UI caller; worker notices and terminal outcomes are drained on the UI thread. Shell approvals remain turn-owned requests dispatched on that thread.
- Stream rendering may coalesce only adjacent `Text_delta` events from the same turn, with fixed byte/event bounds; preserve event order across turn and non-text events. Pace streamed-text repaints at a 60 Hz ceiling even for newline-containing chunks; when a delta arrives before its frame deadline, schedule a wake for the remaining interval so a paused stream does not wait for the one-second activity tick. Completion and other state changes repaint immediately without dropping trailing text.

- `Composer` owns bounded grapheme edits, atomic pasted edits, undo/redo and kill/yank; `Transcript_view` owns sanitized semantic rows, stream rollback, per-call tool settlement/expansion and lazy viewport snapshots. `Tui` maps typed tool lifecycle events to call-owned transcript groups; `run_command` progress carries cumulative received-byte counts only as tool-event metadata, never intermediate output. A successful `read_file` call settles into one sanitized, relative-path-and-line-count row without a first-content preview; each call still independently expands its bounded result in live and restored history, and failures/aborts stay visible. The active matching tool row may show a width-aware byte suffix. `Tui` alone maps terminal keys to these components and repaints changed rows. The CLI renders known typed failure messages once, without OCaml constructor noise; unknown exceptions retain their diagnostic text, and failed provisional text is rolled back before the error block. Do not persist presentation rows or forge provider usage from UI state. Use terminal-safe shortcuts and fallbacks.
- Keep the visible active row to its typed model/tool phase and elapsed time; append cumulative bytes only for the active matching tool when they fit, never as a percentage or instead of phase/elapsed, and omit them when idle. Wrap prose at whitespace when possible and hard-wrap only an unbroken token at grapheme boundaries, preserving the original text.
- Render conversation output as distinct compact user, assistant, tool, note and error blocks with restrained gutters rather than repeated tree connectors. Use dark surfaces: user rows form a filled bubble, tool rows form a card tinted pending/settled/failed with a colored `●` status marker (failed tools and errors use `✗`), and transparent dividers separate blocks; `NO_COLOR` keeps the shapes without backgrounds. The composer is a rounded `╭─ … ─╮`/`╰─╯` box whose top rule carries the Pave version, model identity, saved state, workspace and usage/queue indicators, with keyboard/status hints below it and one spacer row above it; the chrome budget stays four rows. Terminals narrower than 12 columns or shorter than six rows fall back to the bare `❯` gutter. Preserve streaming Markdown styles for headings, prose, quotes, lists, code fences and tables; sanitize untrusted display text. Successful file reads use the compact single-row path/count summary; other settled tools show one outcome row and a bounded, nonempty preview while keeping details expandable, including after resize and cancellation. Remove trailing empty assistant rows on settlement so the final answer occupies a three-row viewport.
- In the TUI, preserve sanitized unified-diff lines in fenced `diff` blocks and recognized printed raw diff output. Highlight file headers, hunk headers, additions, removals, context and metadata with distinct semantic rows; keep added/removed prefixes visible, wrap at grapheme boundaries and retain gutters in `NO_COLOR`. A raw tool result must show its first file header instead of a generic shell-status preview when a diff follows.
