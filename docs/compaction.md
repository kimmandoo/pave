# Context budgeting and compaction

Pave does not infer a context window or tokenizer from a model ID. Supply `--context-window TOKENS` for the exact initial provider, model and API route to enable automatic budgeting; accepted values are 8,192–20,000,000. Changing any of those selections disables that configured budget until restart with the new exact selection. `/context` reports the configured window, prompt allowance, output reserve and byte proxy separately from provider-reported usage.

The estimator compares a conservative UTF-8 byte proxy with the configured token allowance. It counts fixed request/message overhead, system and message text, tool schemas, tool calls and opaque provider-state JSON. It is not a tokenizer, measured token count, provider context limit or guarantee that a request fits. Images contribute an unmeasured count only; their encoded payload and token costs are unknown. An image-bearing context can therefore be over its real provider limit even when the byte proxy fits.

The output reserve is `max(4,096, context_window / 5)`. Automatic preflight runs before every provider request, including tool continuations. It trims only oversized text tool results in the provider-facing copy; the journal's full output remains unchanged. If that is insufficient, Pave summarizes older complete turns in bounded chunks, carrying the prior summary forward. Tool-call/result groups are not split. Generic summary input omits image bytes, retaining only attachment filename/MIME notes; the newest user prompt and its attachments stay in the model context.

## Journal and failure behavior

A compaction marker is appended only after all required summary requests succeed. With an explicit window, automatic and manual compaction also verify that the projected summary plus retained turn fits the same byte-proxy allowance after provider-facing tool-text trimming. Markers are branch-local boundaries; they do not rewrite or delete earlier journal entries, messages, tool output or image artifacts. Reopening, branching or forking reconstructs the summary and retained branch from the journal. If there is no safe older turn, unresolved tool calls, an oversized indivisible turn, an oversized fixed prompt, a failed summary, or an unusable signed prefix, the request fails without writing a compaction marker. The attempted user prompt may already be present in the append-only journal.

The explicit budget is a proxy, not a provider-reported model limit. A system prompt, tool schemas or latest turn can exceed the prompt allowance before any older turn is available to compact; `/context` reports that state and Pave fails closed rather than dropping the current prompt. Image token costs remain unknown.

`/compact` manually summarizes the older prefix while retaining the newest turn. With `--context-window`, generic summaries use the same bounded multi-chunk planner and projected-context check; if the summary plus current system prompt, tool schemas and retained turn still exceed the allowance, Pave rejects the compaction before writing a marker. Without a window, the legacy generic manual path is one summary request with no byte-proxy bound. Native OpenAI Responses compaction also has no local byte preflight when no explicit window is configured; the provider may reject an oversized input, and the journal is unchanged on that failure.

## Provider-native replay

Native compaction is currently limited to the direct OpenAI API-key Responses route (`openai` / `responses`) with an endpoint ending in `/responses`. It calls `/responses/compact` for the exact model, retains the returned native output items as opaque provider state, and binds that state to provider, route and model in the compaction marker. Matching Responses requests replay those items in order; malformed state, model mismatch and responses without a native compaction item are rejected. Manual and automatic compaction use the same route-specific state contract.

Other provider routes do not use OpenAI's compaction endpoint. When signed provider state is still valid for the selected route, generic summarization refuses to discard it. Route/model changes filter out state that is invalid for the new selection; the original journal entry remains available if the user switches back. Anthropic, Codex and other provider-native compaction routes are not implemented because route-specific capability/entitlement metadata and safe native continuation contracts are not established. Do not infer support from a model name or API compatibility label.

A native provider may return only opaque state and no text summary. In that case the journal marker contains a route-bound placeholder rather than a portable semantic summary; another route cannot recover that hidden context from the opaque state. This is a known limitation, not a generic summary. The full journal remains intact, and the matching OpenAI Responses route can replay its state.
