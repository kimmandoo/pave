# Context budgeting and compaction

Pave does not infer a context window or tokenizer from a model ID. Supply `--context-window TOKENS` for the exact initial provider, model, API route and endpoint to enable automatic budgeting; accepted values are 8,192–20,000,000. `--context-window auto` fetches a fresh pinned listing for the exact initial model and accepts Command Code `context_length` plus its advertised API route, Google `inputTokenLimit`, account-scoped Codex `context_window`, Devin Connect `maxTokens`, or Anthropic `max_input_tokens` from its direct API model listing and sole registered Messages route. Anthropic native compaction additionally requires both `capabilities.compaction.supported` and `capabilities.compaction.summarize.supported` to be explicitly true; signed replay is limited to the official Messages endpoint with API-key auth. Listings without per-model route claims are accepted only through a provider's single registered route; custom endpoint overrides, missing limits or unsupported values fail closed. Devin `tokenizerType` is display-only metadata; it does not replace the local byte proxy. Other providers remain unknown unless a verified explicit value is supplied. Changing provider/model/API/endpoint disables the configured budget until restart with the new exact selection. `/context` reports the source, prompt allowance, output reserve and byte proxy separately from provider-reported usage.

The estimator compares a conservative UTF-8 byte proxy with the configured token allowance. It counts fixed request/message overhead, system and message text, tool schemas, tool calls, opaque provider-state JSON and image MIME/base64 payload bytes. Image token costs remain unmeasured; this is not a tokenizer, measured token count, provider context limit or guarantee that a request fits. An image-bearing context can exceed its real provider limit even when the byte proxy fits.

The output reserve is `max(4,096, context_window / 5)`. Automatic preflight runs before every provider request, including tool continuations. It trims only oversized text tool results in the provider-facing copy; the journal's full output remains unchanged. If that is insufficient, Pave summarizes older complete turns in bounded chunks, carrying the prior summary forward. Tool-call/result groups are not split. Generic summary input omits image bytes, retaining only attachment filename/MIME notes; the newest user prompt and its attachments stay in the model context.

## Journal and failure behavior

A compaction marker is appended only after all required summary requests succeed. With an explicit window, automatic and manual compaction also verify that the projected summary plus retained turn fits the same byte-proxy allowance after provider-facing tool-text trimming. Markers are branch-local boundaries; they do not rewrite or delete earlier journal entries, messages, tool output or image artifacts. Reopening, branching or forking reconstructs the summary and retained branch from the journal. If there is no safe older turn, unresolved tool calls, an oversized indivisible turn, an oversized fixed prompt, a failed summary, or an unusable signed prefix, the request fails without writing a compaction marker. The attempted user prompt may already be present in the append-only journal.

The explicit budget is a proxy, not a provider-reported model limit. A system prompt, tool schemas or latest turn can exceed the prompt allowance before any older turn is available to compact; `/context` reports that state and Pave fails closed rather than dropping the current prompt. Image token costs remain unknown.

`/compact` manually summarizes the older prefix while retaining the newest turn. With `--context-window`, generic summaries use the same bounded multi-chunk planner and projected-context check; if the summary plus current system prompt, tool schemas and retained turn still exceed the allowance, Pave rejects the compaction before writing a marker. Without a window, the legacy generic manual path is one summary request with no byte-proxy bound. Native OpenAI Responses and capability-advertised direct Anthropic compaction also have no local byte preflight when no explicit window is configured; the provider may reject an oversized input, and the journal is unchanged on that failure.

## Provider-native replay

Native compaction supports two exact routes. Direct OpenAI API-key Responses calls `/responses/compact`, retains returned native output items as opaque provider state and binds them to provider, route and model. Direct Anthropic API-key Messages uses only models whose pinned `/v1/models` listing explicitly reports compaction and summarize support. It sends `/v1/messages` with `anthropic-beta: compact-2026-09-04`, the `compaction.type=summarize` request field, and the same system prompt and tools as normal inference. A valid response has one signed compaction block and `stop_reason=compaction`; Pave stores its exact content/signature pair as state bound to `anthropic` / `messages` / model.

Matching OpenAI Responses requests replay native output items in order. Matching Anthropic requests place the exact signed block first in the wire-message list and send the compaction beta header on every request that carries it. Malformed, reordered, tampered or model-mismatched state fails closed. Manual and automatic compaction use the same route-specific contracts. Custom gateways, OAuth auth, Bedrock and other Anthropic-compatible routes never receive the signed block or compaction beta; they may receive only the visible summary text. Generic summarization refuses to discard a signed prefix valid for the selected route. Route/model changes filter provider state from the outgoing history while leaving the original journal available if the user switches back.

OpenAI Responses may return opaque state without a text summary; that marker uses a route-bound placeholder and another route cannot recover the hidden context. Anthropic returns summary content with its signature, so other routes retain visible summary text but strip the route-bound signature. Neither behavior rewrites the full append-only journal.
